# 经营目录名称与业务快照修复

用户已确认现有分段重算计价算法正确，本次不改变计价规则。风险为 A 级：换房事务快照构建与错误回执分类。

## 行为约束

- 业务 `loadInventoryUnit` 返回数据库原始事实，活动状态只决定可操作性，不改变名称。MOVE_UNIT 预览、确认、数据库组合保护使用同一份语义；库存、容量、版本和事务保护均保留。
- 当前 RESERVED / CHECKED_IN 订单展示和搜索使用经营目录房型名。列表在分页前使用同一表达式筛选及展示；详情只读接口增加可选 `display_name`，原始 `name`、业务内部快照、历史记录不改写。终态订单和停用单元保留原名。
- 事务异常保留拒绝回执和幂等恢复流程。只允许 PostgreSQL 明确中止的序列化冲突、死锁、锁不可用和取消错误提示重试；约束错误、未知异常及结果不明的网络错误不得鼓励盲重试。日志只记录命令类型、服务端预览 ID、关联 ID 哈希、SQLSTATE、合法约束标识和分类，不记录 SQL、参数、完整异常或业务个人资料。

## 自动验证与人工验收

- 回归：经营目录首次维护后，普通/会员、整房/床位、人工目标价及改期后续换房；保留拒绝非法容量和库存冲突的测试。
- 更名后新建及已有订单当前展示和名称搜索一致；历史及停用单元保持原名。
- 约束异常可诊断且不可盲重试；明确瞬态错误仍可重试；日志脱敏、拒绝回执及恢复验证。
- 人工验收（待执行）：在测试环境维护目录后新建订单并换房；房型更名后检查列表、详情、搜索及历史；核对原始 7 晚分段报价与人工目标价。工程通过不等于人工验收或生产部署完成。

## 发布与回退边界

没有新增数据库迁移或生产数据修正。发布后，旧版本生成但尚未确认的预览可能因规范名称变化被判定 `PREVIEW_STALE`，应重新生成预览后确认。回退应用不需回滚数据库，但会恢复原有的目录维护后换房失败风险；本次未发布。

新增 `npm run test:catalog-regression`，在已持久化经营目录的夹具上复用七组生命周期集成测试，并加入 CI 的 PostgreSQL 18 job。首次正式目录写入、名称与分页搜索、历史保留、异常分类和回执重放由 `catalog-snapshot-regression.integration.test.ts` 另行验证。复杂多阶段故障注入用例使用 120 秒超时，业务断言和数据库保护不放宽。
