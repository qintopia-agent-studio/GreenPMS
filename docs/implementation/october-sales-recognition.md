# 2026年10月起的经营销售额统计口径

统一交付与状态以 [经营销售额、渠道退款与看板统一交付清单](sales-reconciliation-delivery.md) 为索引。

状态：企微匹配日期、按份额计入、防重和9月衔接已于2026-10-15获用户确认；会员售卡收款时计入也已获用户确认；新统计已进入开发验证，尚未上线。9月按用户确认的封账基准保留，具体业务金额和确认材料在本地忽略目录。

## 已确认规则

- PMS为经营事实的权威来源，不依赖飞书运行。
- 企微只收到钱、不匹配业务，不计住宿收入。成功匹配住宿订单后，只按本次有效匹配份额计入，收入日期取匹配完成的PMS日期；先建房态、后匹配时不回到原建单日。
- 渠道订单形成有效房态占用，关联渠道订单号及应结金额后，按该次录入房态日期计入渠道应结金额。
- 换房、占用重建、内部划转以及渠道款随后转企微不重复产生收入。
- 9月已计收入的款项需保留依据；10月补匹配不能再次计入。自2026年10月起采用新规则，不静默重算9月已封账基准。
- 正常流程复用原订单和收款/退款入口，不新增独立补录页面、月度核对状态或额外确认流程。

## 已核对的系统事实

建单、住宿收款登记、会员收款登记、会员生效是独立动作。支付流水occurred_at、订单created_at、分配记录created_at分别表示支付、建单和匹配登记时间。住宿支付可按份额分配；会员收款仍整笔关联会员订单。仅创建会员订单不代表已收款；会员权益生效也不是一笔新的资金收入。

## 已确认会员售卡口径

用户明确认可售卡真实收款登记时计入，具体采用：真实收款成功登记到会员订单时计入已收金额，日期取该次PMS登记/匹配日；无需等待入住核销或会员生效，也不以未收齐的合同总额先计满。

权益入住不再次产生销售收入；额外真实补差按对应业务匹配金额计入。已有住宿款转会员属内部归属转换，仅新增真实补款计为新收入，避免把已计住宿款或9月封账款再次加到会员销售额。会员退费不是当前已有的通用功能，不以收款更正或删除会员冒充退款；后续退款口径与功能须明确区分。

## 实施状态

正式统计事件、跨来源防重、期初承接、渠道退款、看板组成明细和同版本员工知识已实现，正在进行真实数据库与页面联合验证。历史数据正式更正、生产初始化、人工验收和发布尚未完成。不能把规则确认或本地验证等同于上线。

## 实现中的内部模型与验收边界

渠道成交、实际退款、金额纠错和误录撤销使用独立追加式事实，不能伪造为企微收款。已有渠道修订在迁移中按原时间承接；取消/未到不自动生成退款。正向住宿金额调整仅登记超过当前已确认净额的部分，负向合同变化不假定平台已经退款，实际退款另记；REPRICE_ORDER错误更正在当前应结与已计余额一致时按合同差额修正原业务日期；存在待退差额时不得因更正或同价操作重新计入已保留的收入，来源不一致时拒绝并要求核对。原业务日期取最近一次真实改变合同金额的住宿变更，跳过同价换房和备注更正。出现退款后又有成交/金额更正时，原退款的误录撤销必须先核对后续链，不能无条件恢复旧状态。上述组合需要真实数据库验证，未通过不视为完成。

新统计只读现有业务及追加事实，未匹配账单不进入收入。对同一来源账单的有效关联总额超过账单金额时标为待核对，不能任取一笔。期初承接默认只读校验、显式所有者写入、计划SHA核对；没有期初来源承接不开放渠道退款，也不显示完整经营销售额。9月完整月份使用批准的封账基准，部分日期不能虚构拆分。

渠道退款在同一命令事务中同步当前应结：若尚未因缩短/取消下调，则降低到不高于退款后的经营净额；原成交与原计价修订保留，已取消的0元不会再减一次。核对页展示调整前后应结金额，不改住宿范围或库存。误录撤销只恢复该退款实际造成的应结变化；其后若有新的定价或成交变化，先拒绝自动恢复以保护后续业务链。退款号通过独立的当前占用索引保证并发唯一，历史事实保持追加；提交时同时校验正式命令回执和计价更新。

住宿款转会员保留原真实收入，内部转入不新增收入。会员同一流水的连续备注更正沿原匹配链保持首次登记日期。期初已计额度按稳定账单身份承接，不能随资金事实ID变化而失效。

期初份额按原登记及实际冲销时间承接。例如同一600元流水，9月A已匹配300元、10月2日B再匹配300元，10月3日解除A并重新匹配时，B的300元仍归10月2日；不能把旧A的期初额度提前用于B，再把收入移到A的重新匹配日。账单级部分额度与事实级额度都须保持这一规则。首次初始化按口径切换截止时的来源有效性校验，截止后发生的更正不抹掉当时的已计依据。
