# AI 助手 V1 实施规格

## 2026-11-05 主备供应商与恢复检查（已实现，真实供应商待验收）

用户已确认本节方案并授权实现、提交、建立PR、合并与正式部署。本节覆盖此前“失败不自动重试”的规则，保留60秒首次有效响应/连续静默期限，以及持续有效响应无累计时长上限。不得改变资金、库存、业务确认、工具白名单或权限边界。

- 一主一备，每家独立名称、HTTPS Base URL、加密Key、模型、启用状态与测试状态。仅原管理门店ADMIN可配置；普通员工不可见地址、模型、测试详情或凭证。已有线上主配置迁移后原样继续使用，不把历史配置伪标为已测试；新增/重新启用/改变连接后须真实测试。测试回执绑定管理员、会话、门店、配置版本、供应商角色和连接指纹，不能由浏览器伪造“测试通过”。测试不保存配置；地址变化须新Key。
- 设置页两张供应商卡片，分别测试/保存；备用卡“设为主用”原子互换完整配置，不需重填密钥。只有已启用并已测试备用可提升。人工保存/互换递增配置版本、使旧会话失效并停止旧请求，界面明确提示；自动切换不修改配置或管理员指定的主备身份。停用全局或某供应商无需联网/旧Key解密，并禁止后续调用/探测。
- 主供应商连接、DNS临时失败、首次/静默超时、服务错误、限流、明确供应商凭证故障可触发可用性处理。安全URL/DNS地址检查、证书校验、PMS鉴权/权限、配置变化、取消/断网、业务工具和请求校验错误不触发备用；不得只看HTTP状态把PMS的401/403当供应商错误。供应商正文不进入日志。
- 一次提问累计未向用户输出任何文字、未执行任何工具时，允许取消主请求后自动切备用一次。仅收到推理或未完成工具参数的失败尝试可丢弃重做；主仍持续有进展不因慢而切换。选择备用后该问题所有后续模型轮固定备用，无回切/循环。失败尝试计入原4次模型请求上限，工具6次上限保留。后台恢复检测单独计为维护请求，不占用用户问答调用额度。
- 已输出文字或执行工具后失败，不自动接续；满足当前权限和备用可用条件时返回安全的“可用备用重试”标志。页面提供“用备用重新回答”，明确重新生成原问题、保留此前成功对话、不拼接半截回答；停止、换店/退出、配置变化不提供自动重试。手动请求只允许选择已配置备用，不接受外部URL/模型/Key。
- 主故障后暂停主600000毫秒，有可用备用时新问题直接用备用。到期有新问题时该问题仍走备用，同时启动单个独立合成恢复检测；不发送用户问题/业务上下文、不阻塞用户、不在无请求时后台定时发起。完整流式协议和`connection_check(ok=true)`通过才恢复后续问题优先主，失败后重新等待10分钟；只收到响应头、心跳或部分输出不算恢复。已在备用上进行的问题继续完成。没有可用备用时保留主正常尝试与明确错误，不能因为冷却让唯一可用配置永久不可用。
- 管理员“立即检查恢复”复用同一个检测，不并发重复；结果与启动时配置版本绑定，配置更改、关闭助手、应用关闭会取消检测，迟到旧结果不能恢复新配置。检测使用短合成消息及有限输出，沿用60秒首响/静默和响应大小上限。路由状态沿用现有单API实例内存生命周期，不增加调度器/共享服务；重启按保存配置重新从主开始。
- 管理员可看临时备用/检查中、下次可检查时间、最近安全失败码和检查时间；员工仅看到必要阶段提示。日志记供应商角色、切换/检查原因和耗时，不记Key、模型正文、工具参数/结果。主备任何一路都受原权限、会话、门店、频率和停止规则约束。

接口沿用GET/PUT `/api/v1/assistant/settings`与POST `/api/v1/assistant/test`，增加可选供应商角色/名称/启用/测试回执；新POST `/api/v1/assistant/promote-backup`与`/api/v1/assistant/recover-primary`均要求门店与expectedVersion。聊天增加受控`useBackup`选择，SSE增加`fallback`阶段和`backupRetryAvailable`标志。新增迁移079扩展原单行设置、受控函数与审计，不覆盖历史迁移或业务记录。

## 2026-11-04 按有效响应续期（用户已确认）

本节覆盖下方历史版本的 60 秒模型请求总截止、120 秒整轮预算和150秒浏览器总截止。用户确认：首次有效模型响应最多等待60秒；开始响应后连续60秒无有效增量才超时；持续有进展不限制累计时长，人工停止立即取消上游，失败不自动重试。

- 有效进展包括通过协议校验的非空文字、思考增量、工具调用标识/名称/参数。思考仅在服务端处理，不展示推理正文。响应头、SSE保活注释、空增量、仅usage帧不刷新模型时钟；结束仍要求完整 `[DONE]`。DNS保留5秒独立上限。
- 所有供应商请求统一流式传输；旧JSON网页客户端仍在同一次请求内汇总返回最终JSON。单轮最多4次模型请求、6个工具，响应大小/字段长度和业务确认边界保持原约束；有效进度触发每秒至多一次权限/配置复核，覆盖只有思考/工具数据的长流，显示文字和执行工具前仍复核。
- API生命周期只在连续120秒没有模型有效进展或内部依赖完成时终止卡住的查询，不限制问答总时长；服务端每10秒发送的浏览器心跳不刷新此保护。浏览器仅在连续150秒未收到服务器响应数据时断开，任何非空网络数据含服务端心跳可证明连接仍活跃；这不改变服务端模型60秒静默判断。
- 提问记录以有效进展限频刷新活跃时间，避免仍在生成的长回答被10分钟维护规则标成中断；失去进展的记录仍会回收。同步追加迁移078，不修改历史迁移或业务数据。
- 回归重点：超过原60/120/150秒持续输出成功、仅思考/工具增量可续期、只有心跳不能维持模型、首次与中途60秒静默、主动停止、断开与权限失效、长于10分钟问答记录/反馈和清理。真实模型/页面人工验收单独记录；自动合成验证不代表真实模型已验收。

本地工程验证（Node22）：1973项全量单元测试通过；审阅修正后127项相关回归、类型检查、前端构建、8项PR格式测试通过；独立PostgreSQL18助手契约32项通过（含权限、长问答记录与安全函数漂移），发布harness185项离线测试通过（Python3.12）。CI流程和保护配置未修改。真实慢模型人工验收仍待进行。

## 2026-09-20 流式响应与抽屉修复（已实现并通过自动验证，待人工验收与发布）

- 对话继续使用同一 POST 接口，浏览器以 `Accept: text/event-stream` 请求 SSE；旧 JSON 客户端保留兼容。事件仅包含阶段、当前轮次、回答增量、最终结果或安全错误；不转发供应商原始事件、工具参数、推理正文或密钥。
- 模型使用 Chat Completions `stream:true`，按 index 拼接 function tool 的 id/name/arguments；收到完整结束标记并验证后才执行工具。依据官方 openai-node ChatCompletionChunk/Delta.ToolCall 契约（2026-09-20 核对）。不自动重试或降级再次计费请求。

## 安全与接口

- A 级边界：密钥管理、读取授权、入口门禁；现有资金/库存/生命周期规则不变。
- 服务端 AES-256-GCM 加密 Key；独立环境变量 `AI_SETTINGS_ENCRYPTION_KEY` 为 32 字节 base64 密钥。不写入浏览器存储、响应、日志或审计。未配置该环境变量时仅 AI 不可用，不影响 PMS。
- HTTPS 公网地址；拒绝 userinfo/query/hash、私网/环回/链路本地等目标。DNS 每次校验并固定连接地址，拒绝重定向；超时和响应大小有上限。地址变更必须重填 Key。
- 设置持久化、版本 CAS 防覆盖、数据库写入函数重验活跃管理员会话，审计只记录版本/操作人/地址/模型/密钥是否替换。
- 每个模型工具调用重新验证当前会话和门店权限；工具参数白名单，服务端绑定 propertyId，不允许模型指定任意 URL/SQL/命令/门店。查询仅最小必要字段，屏蔽证件号/完整手机号/外部交易号。
- 会话仅服务端短期内存与当前浏览器内存；绑定用户、登录会话、门店、配置版本。切换门店或退出清空，过期明确提示新建。不持久化聊天明文。
- 每轮最多 4 次模型请求、6 个工具调用；限流、单会话并发锁；失败不自动重试计费请求，不宣称操作已完成。
- 导航目标由服务器工具生成；前端再次白名单校验。表单开启复用正式按钮门禁，无自动 Confirm/提交。
- 回复仅允许排版标签，使用 `react-markdown` / `remark-gfm` 解析；`skipHtml` 忽略原始 HTML，标签白名单不含链接、图片、表单和控件。模型提供的链接只保留文字，不能绕过正式入口导航。用户输入和手机号脱敏、算式中的字面星号保持原意。
