# AI 助手 V1 实施规格

状态：2026-09-15 工程完成；自动检查通过；真实模型与业务人工验收待进行，未部署。

## 已确认行为

- 全局入口位于左导航底部门店上方；右侧浮层覆盖日历，禁止改变日历宽度与滚动位置。手机全屏。沿用现有绿色、系统字体、5px 控件圆角、Lucide 图标和抽屉阴影；现有品牌资源 `apps/web/public/qintopia-logo.png`。
- 解释操作、查询获权房态/订单/会员；直接打开预定义页面或正式表单，并持续显示该入口的操作说明。仅用户在正式表单提交；模型无任何业务写工具。
- 管理员在设置页随时配置、替换、停用并测试 Base URL / API Key / 模型。协议为 OpenAI Chat Completions（非 Responses）；必须支持 function tools。官方契约核对来源：https://github.com/openai/openai-node/blob/master/src/resources/chat/completions/completions.ts （2026-09-15）。
- 本次一套 installation 配置，首次配置绑定管理门店；仅该门店当前 ADMIN 可维护。其他门店仅使用服务；不把门店伪称 SaaS 租户。未来 tenant scope 须由 SaaS 契约定义。

## 安全与接口

- A 级边界：密钥管理、读取授权、入口门禁；现有资金/库存/生命周期规则不变。
- 服务端 AES-256-GCM 加密 Key；独立环境变量 `AI_SETTINGS_ENCRYPTION_KEY` 为 32 字节 base64 密钥。不写入浏览器存储、响应、日志或审计。未配置该环境变量时仅 AI 不可用，不影响 PMS。
- HTTPS 公网地址；拒绝 userinfo/query/hash、私网/环回/链路本地等目标。DNS 每次校验并固定连接地址，拒绝重定向；超时和响应大小有上限。地址变更必须重填 Key。
- 设置持久化、版本 CAS 防覆盖、数据库写入函数重验活跃管理员会话，审计只记录版本/操作人/地址/模型/密钥是否替换。
- 每个模型工具调用重新验证当前会话和门店权限；工具参数白名单，服务端绑定 propertyId，不允许模型指定任意 URL/SQL/命令/门店。查询仅最小必要字段，屏蔽证件号/完整手机号/外部交易号。
- 会话仅服务端短期内存与当前浏览器内存；绑定用户、登录会话、门店、配置版本。切换门店或退出清空，过期明确提示新建。不持久化聊天明文。
- 每轮最多 4 次模型请求、6 个工具调用；限流、单会话并发锁；失败不自动重试计费请求，不宣称操作已完成。
- 导航目标由服务器工具生成；前端再次白名单校验。表单开启复用正式按钮门禁，无自动 Confirm/提交。

## 验证和人工验收

自动验证：密钥加解密/脱敏、地址和 DNS 限制、管理员/员工/Token/跨门店隔离、版本竞争、工具越权/异常/超时、真实 function-tool 循环协议、入口直开且无提交、1440/768/375px 不挤压日历与显式关闭。

人工验收登记于主验收计划：1. 管理员配置真实服务、测试、改模型并重新测试；员工不可读写配置。2. 提问查询、打开订单/续住表单并阅读说明；由人取消或提交。3. 日历尺寸和位置保持、手机面板可关闭、换店不串话。

真实供应商兼容性需在用户于设置页提供服务后验收；自动测试使用本地合成模型响应，不作为真实模型通过证据。
