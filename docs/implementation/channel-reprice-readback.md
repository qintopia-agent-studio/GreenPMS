# 渠道金额更正后的订单详情读取修复

2026-10-15，生产v1.13.0：两笔外部渠道订单完成REPRICE_ORDER后，后端已经提交新金额及合法追加计价修订，但前端详情页报“amounts.currentContractAmount与最新住宿安排计价摘要不一致，且没有合法的后续独立调价记录”。

根因是`parseOrderView`在当前合同金额与住宿安排历史金额不同时，仅接受普通人工调价、恢复政策价和会员调价，漏掉CHANNEL_CONTRACT独立金额更正。住宿安排没有变化，所以其历史金额不应被追溯覆盖。

修复只在既有严格调价证据链成立后接受CHANNEL_CONTRACT：订单属于游牧岛、携程或美团，无会员关联且非免费，人工调价额保持0。原REPRICE_ORDER amendment唯一性、订单ID、原因一致性、日期顺序、当前修订指针、币种与金额等检查全部保留。此变更不新增写操作、不修改历史金额、不增加迁移。

验证：两份生产只读DTO在旧解析器均复现同一错误，修复后均通过；真实资料只保存于本地忽略目录。新增11项回归，包含在住/已退房、三渠道与两种角分目标，以及非渠道、缺少更正依据、错误原因、跨单、非零人工调价、时间倒置拒绝。全量98文件1605项单测、类型检查、构建和PR格式检查通过。

助手知识核对：本次只恢复此前已确认的渠道金额更正详情展示，不改变员工入口、权限、操作步骤或业务语义，沿用2026-10-15.2的booking/pricing知识，无运行时知识变更。
