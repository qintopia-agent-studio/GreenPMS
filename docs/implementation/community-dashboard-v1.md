状态：2026-10-12 v0 重设计及统计修正已实现，待视觉反馈与真实业务人工验收；类型检查、完整浏览器验收及数据库验证仍有阻塞，不宣称工程全部验收通过。用户已授权实施此前逐项确认方案。下方既有保留库、旧版截图和检查记录来自交接版本，不是本轮 v0 环境的验证；本轮状态以末尾“v0 重设计交付”一节为准。

## 确认规则

首屏依次为社区人数、居住变化、房源与资金。人数与销售单元不得混用；收费含会员权益及应收费欠款住宿，免费按已有义工/接待细分。每日入住趋势使用实际住宿，未来只展示有效预订及在住延续。连续同住客同门店无空夜跨单换房属于续住，间隔后回来属于复购；实际住宿时长不计尚未履约未来夜。长短住不设业务阈值。用户于2026-10-12确认：当前在住（人）和所选期间全部（次）统一按六档展示实际夜数。当前在住固定今天，不随历史日期变化；所选期间全部包含期间实际住过、截至统计截止日仍在住或已离店的连续住宿，不含仅预订未入住。统计截止日取所选结束日与今天中较早者，从本次连续入住累计到离店或截止日，不只累计期间内的夜数；离店日不计入住，期间首日已离店的不纳入，截止日当天入住计0晚，纯未来区间没有实际住宿。同人有空夜再来分别计次，跨单换房和重叠住宿不重复计次。两组可重叠，但历史全部不是今天在住的必然超集。六档为：不足1周（≤6晚）、1–2周（7–13晚）、2–3周（14–20晚）、3周至1个月（21–30晚）、1–2个月（31–60晚）、超过2个月（≥61晚）。月按固定30晚，不随自然月变化；只在展示层合计原始逐晚数量，底层精确夜数、未来夜排除和业务长短住规则不变。有数据时保留零值档，无可核对时长保留空态。提前退房根据有效业务事件与原始原因，不推断满意度；社区参与、目标、安全线、预测均不做。

经营入住率沿原销售单元口径：独立整房1、单床1、拆床包房按该日床数折算；维修和免费不减总分母。期间率使用逐日分子合计/逐日分母合计。新增和结构变化只影响有效日期后。复用日容量基础逻辑，不能把当前结构倒灌历史。

## 实施边界

只读API与界面，不增加迁移、seed、生产连接或配置后台。住客跨单证据优先既有稳定身份，不能按姓名或共用手机猜测；没有身份或历史入住人证据的指标明确给出具体原因，保留可核对登记数，不冒充去重人数。实际库无目录变更且无住客身份证/电话的验收资料只是低完整度样本，合成回归必须覆盖真实边界。

UI：保留原框架与视觉体系；房型楼栋分列、付费住宿量占比。按 2026-10-20 用户反馈，逐日住宿和资金表的标题与单元格居中对齐；未来已订和楼栋房型的数据表均为七列等宽布局，标题与内容居中，统一行内留白，合计对应原列；窄屏保留表内横向滚动。逐日人数与统计依据表按日期倒序，最新日期在上，人数趋势图继续按时间正序。付费住宿量占比仅显示百分比，去掉绿色条。未来卡片改事实曲线；名词和空值原因沿InfoHint样式，补触屏和关闭支持。大面积警告只用于明确数据错误，不把全店因历史问题变未知。

## 验收

1. 跨单无空夜连续实际40晚只构成一次居住，回访另计；同一人同日只计1人；免费/收费冲突有说明而不任意归类。
2. 原单延长与跨单续住可追溯，提前退房撤销不计，换房接单不计社区离开；不同实际时长精确分布。
3. 目录变更按生效记录重放，维修不改总量，纯改号不影响；缺历史基线只影响相关日期，当前可用库存不因历史价款/容量证据而清空。
4. 类型、现有相关单元、新回归、只读保留库、浏览器验证；不运行数据库reset型测试。工程通过与业务人工验收分开。

## 实现与限制

- 新增daily-sales-capacity，以正式库存新增/退役版本重建逐日规模；复用到房态和经营概览。目录命令为即时生效，按门店时区的正式记录日期归属；没有业务启用证据的初始目录不回填记录之前的规模。新建/退役记录残缺、停用缺少事件时解释具体原因。维修不进入总容量扣减。
- 社区统计通过有效订单时间线、住宿人和更正记录读取，原身份只在服务端使用，不向响应暴露证件/电话/关联键。暂只用明确证件依据跨单去重，不用同名/共用电话或付款会员身份猜实际住宿人。缺证据的关系影响相应日期/统计范围，不能替代完整人数；历史新增/移除成员缺少住宿日期时同样提示具体订单。
- 连续住宿合并同住客相接区间；同单换房不算新续住，未来确认接单不计已住时长；到期列表排除已确认接续预订。人员变化标签明确计可追溯记录，不冒充独立人数；提前退房事件复核相邻CHECK_OUT及REVOKE_CHECK_OUT，保留原原因。
- 未来占用分类从正式有效库存占用读取，不依赖历史价格/容量校验。正式可售查询成功时保留数字；确实缺少某类库存查询结果才令该类为空，未知阻断不会转成可售。
- 已同步助手dashboard知识；图标沿用现有说明视觉，补可点击、关闭、焦点和移入阅读，并通过portal避免表格裁切。房型楼栋单行分列，增加原销售单元口径的付费住宿量占比。未来以事实曲线+日期选择和明细表呈现，不设目标/安全线/预测。
