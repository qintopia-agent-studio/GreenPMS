# 渠道退款后的房态与订单详情读取

2026-10-29。依据已确认的 [渠道退款与应结同步规则](october-sales-recognition.md)，修复读取兼容。已实现并通过自动验证；人工业务验收、合并和生产发布尚未完成。

## 行为与边界

游牧岛、携程、美团订单的正式渠道退款可以将当前应结降为零。退款后的零应结不是缺少原成交资料，也不等于取消住宿、免费入住或平台实际到账。原成交、退款、计价修订和住宿历史仍可追溯。

历史已退房订单在来源、生命周期、计价和全退事实均一致时，房态仍显示已结单，不能因此让整页变为资料待核对。零应结须关联同订单同币种原成交、未被撤销的渠道退款、成功命令与回执、对应金额修订及后续合法金额更正链，渠道净额（含期初已退）须为零。缺少或矛盾证据继续 UNKNOWN/PARTIAL；普通企微正金额规则和全局写入门禁保持原有规则。

订单详情承认正式渠道退款及误录撤销产生的独立金额修订，核对原金额、目标金额、币种、住宿日期、原因与同单渠道事实。此兼容覆盖预订、在住和已退房的可读状态，不把部分退款或全额退款伪装为 REPRICE_ORDER。既有操作是否允许仍由订单状态、权限和服务端核对决定。

## 验证与验收

1. Given 三种渠道的合成已退房订单，When 部分退款、分次全退至零、撤销退款后读取，Then 正式 API 响应可被前端解析，历史房态 READY/SETTLED，库存事实不增加，其他今日订单保留符合状态的入口。
2. Given 先缩短住宿并下调应结、原成交尚未退款，When 按原成交全额登记退款再撤销，Then 当前金额和渠道净额分别正确变动，住宿范围、退房状态和库存保持真实历史。
3. Given 缺少退款事实、跨单、币种或金额矛盾、伪造零金额修订，When 读取，Then 继续拒绝或标资料待核对；不通过放宽所有零金额掩盖异常。

沿用现有数据库测试锁、单元测试、类型检查和构建；不修改 CI、发布入口或新增迁移。真实生产金额差异不属于本修复自动更正范围。人工验收见主计划新增检查点；测试仅使用合成数据。

- 126 个文件、1947 项单元测试通过；覆盖三渠道预订、在住、已退房的退款修订、分次退款及两种撤销顺序、期初已退、同毫秒时间序列和矛盾目标金额。
