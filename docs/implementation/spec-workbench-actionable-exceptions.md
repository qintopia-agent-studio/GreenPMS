## 业务规则

- 异常代表存在具体未完成事项。正常 `CANCELLED`、`NO_SHOW` 不因状态或原住期覆盖今天进入异常。
- `RESERVED/PLANNED` 到店日早于门店当前营业日：逾期未到；`CHECKED_IN/IN_HOUSE` 离店日早于营业日：逾期未退。当天应离店不算逾期。已标记未到不再保留逾期到店原因。
- 普通订单 C=当前合同金额，N=所有有符号资金事实净额（含退款、冲销、内部划转），L=当前有效剩余客户留存。有效预订/在住/已退房订单 N<C 显示欠款待收，不另设宽限期；N>C 时未处理多款为 max(N-C-L,0)，取消/未到/撤销入住显示应退未退，其他订单显示多收待处理。
- 取消、未到及撤销入住的当前应收应为零；已退房订单仍保留实际合同金额。负净收款、负留存、留存超过多余资金或来源可用份额等不一致需明确待核对，不能靠留存掩盖少款。正常留存不是异常。使用/退款后按剩余留存重算；解除留存后尚未退款的金额重新进入异常。
- 免费住宿不得产生正常应收；会员权益住宿按既有金额/权益事实判断，不把权益抵扣当现金欠款。
- 外部渠道使用当前渠道应结与渠道经营净额（含销售、更正、退款、冲销、期初退款），不以普通收款为零认定欠款。取消后渠道净额仍为正显示渠道退款待处理；已登记全额渠道退款净额为零不报。未初始化/应有事实缺失显示资料待核对，不宣称平台实际到账。历史渠道订单遗留的普通收退款或留存余额须单列资金待核对，不能与渠道净额相抵或因渠道退款完毕而隐藏。
- 终态残留有效库存占用、未释放预留权益、订单与住宿状态不一致，显示明确原因。不能因某笔数据不一致把整批解释成没有异常。
- 资金和资料异常不受原住期/页面浏览日期限制，直到相关事实解决。每个订单计数一次，多个原因全部显示。查询失败/分页未加载不等于零异常。

## 接口与界面

新增只读 `GET /api/v1/workbench/exceptions?propertyId=...&afterId=...&limit=50`，门店 READ 权限，最大100条，按 orderId 升序分页。响应包含 propertyId、businessDate、asOf、totalOrders、items、nextCursor；计数是当前门店全部异常订单数，非当前页长度。

每项包含 orderId、orderStatus、stayStatus、guestName、arrivalDate、departureDate、unitLabel、orderHref 和 reasons。原因包含 code、category、message、amount（金额或null）。分类为 FULFILLMENT、FUNDS、INVENTORY、DATA。页面和外部客房智能体可读取同一结果，API 返回原因不赋予业务写权限。

工作台保留现有四个分类；异常页改读上述接口，展示原因、差额和查看订单入口，支持分页。其他分类继续现有查询，移除其中已取消/未到的纯日期候选。现有收退款、留存、取消、入住退房命令及保护流程不变。无需数据库迁移或 CI 流程调整。
