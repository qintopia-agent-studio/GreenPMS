# 看板登记人数与补录房源历史统计修复

## 问题与边界

运行正常的看板可能因住宿人未填证件号而隐藏当前和历史人数：实现把“缺少跨单关联”错误地等同于“没有可统计登记”。即使有稳定住宿人登记ID及实际日期，原分类也只累计能跨单关联的住客。

保留原跨单去重、续住、复购口径，不凭姓名、共用手机或下单会员猜身份。独立返回按稳定登记ID逐日去重的登记总量及付费/义工/接待分类。跨单身份不足时，当前现场和整段趋势明确使用“登记在住”，日均也按同一口径；不把登记数量替代本期去重接待、连续居住或复购人数。真实名单/日期缺项仍不能猜人数，旧API无新增字段时不伪造0。

## 实施

- 领域层新增registered日汇总，不改变原total与visitors。
- 契约及响应Schema同步新增可选字段。
- 前端当前卡片、整段曲线、日均、逐日表统一选择证据口径，并就近说明尚未跨单合并。保留v0视觉结构。
- 助手dashboard知识同步，提示缺证件不等于无人入住。
- 用户已确认两间房在8月底已使用、9月15日只是补录。按限定库存版本、录入时间及最早可证实使用日期补充读取依据；看板与房态共用，恢复相关日期分子和分母，原始审计不变。更早日期和未确认房源不外推，详见`confirmed-inventory-availability.md`。

## 验证与交付

真实环境通过独立一次性只读进程加载修复后的纯函数，使用原正式加载器做对照；未替换容器文件、未改变服务、未写库。结果证明现有登记人数与分类可恢复，历史登记趋势完整；私有诊断原件只留本机忽略目录，不随代码提交。

回归覆盖：无证件但有登记ID；同一登记跨区间不重复；不同订单登记与同一身份人数分别计算；缺名单不可推断；混合资料时整段趋势口径一致；响应Schema；实际卡片SSR渲染。相关原有统计/加载器/助手检查保留。实施不修改CI、写入门禁、计价、资金或业务原始记录，不包含生产发布。

验证结果：7个相关测试文件64项通过；Node22类型检查、release:check及正式构建通过，PR格式校验器8项通过。首次本地扫描包含忽略目录中的交接源码副本，正式结果已明确排除本机归档副本；未修改CI或测试入口。

2026-10-13用户确认后补充：两间补录房源的确认读取依据已实现，和登记人数修复一起通过12文件148项回归；看板及房态共用同一依据。生产同快照只读对照确认当期入住率可恢复，未来/资金/当前汇总不变；原数据库和运行服务未修改。
