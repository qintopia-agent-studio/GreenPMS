# 经营概览专项审阅修复

2026-10-11，用户授权修复已复现的三个问题；沿用经营概览既有统计、权限和只读事务约定。

## 范围与验收

- 未来订单时间线无法核对时，保持原日期集合和隐藏可售数行为，额外保留每笔异常订单的只读明细，标记影响区间及原因类别。预订同样可追溯。未来事实不受历史日期、楼栋、房型或来源筛选隐藏。概览新增futureReviewCount表示未来异常订单记录数，与每日原有异常标记区分。历史及未来分别构成核对事实，同一订单可有两条不同范围的事实。
- REVIEW明细合并历史、资金和未来核对事实；需关注事项计数包含未来明细。未来区提供查看待核对事实入口。使用原订单链接和既有READ门禁，不增加写能力，不向响应暴露内部异常文本。
- SAVE_ROOM只有具备完整roomRename证据且明确无新增/退役库存时，才排除容量变更；新增、退役、启停及证据不完整情况继续保守处理。
- 审阅纠正：页面原本已经禁用月初按钮，正常点击报错的原结论不成立。本轮补充事件处理防御和禁用原因提示。每月1日禁用“本月至昨日”，提示没有完整营业日；事件处理也拒绝生成反向范围。其他日期保持本月1日至昨日，不悄悄切换统计口径。

自动验证：无数据库写入的加载器回归覆盖异常预订、影响区间裁剪、纯改号与真实容量变化；日期覆盖月初、月中、闰年；核对摘要计数、明细与公开响应字段；运行类型检查及相关现有单元测试。真实保留库仅做GET冒烟。禁止迁移、seed、重置及会清库的契约/E2E入口。

人工验收待本轮实现和自动验证后进行，不能沿用上一轮UI验收作为本轮业务修复通过。

## 实施结果

上述修改已实现。相关49项测试、类型检查及保留库只读摘要/明细一致性验证通过；真实异常业务样本人工验收待完成，未写入数据库或运行重置测试。月初原禁用保护的审阅误判已更正。
