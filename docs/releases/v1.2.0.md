# QinTopia PMS v1.2.0

发布日期：2026-09-09。基于用户旅程审查完成 F01–F15 读取可靠性、恢复路径、入口衔接和界面信息架构优化；Git 标签 `v1.2.0` 对应本次应用发布提交。

## 优化说明

- 读取可靠性：避免订单详情和房态慢响应被轮询或新鲜度门禁丢弃；后台刷新失败时保留当前内容与未提交表单，并给出可恢复的状态说明。
- 数据一致性：订单列表、详情、今日工作台和会员入口使用当前住宿人及当前房源信息；订单列表支持房号/床位识别、分页和返回后保留筛选上下文。
- 入口与工作流：会员详情可直接进入安排住宿并预填会员身份；旧账号、Token 和新建住宿入口继续兼容并归入清晰的设置/房态工作流；设置账号页提供语义图标及低频区折叠。
- 房态与订单筛选：销售模式、房间/床位和容量归入可展开的更多筛选；新建住宿与刷新房态保持同一行；订单资金筛选改为明确的“收退款核对”入口，并显示范围提示。
- 失败反馈：区分登录失效、权限不足、读取失败、库存过期、结果未知和业务校验失败，默认向操作者提供原因与下一步；技术细节保留在可展开诊断信息中。
- 性能：会员历史候选、订单目录和住客查询改为按资格过滤、分页和索引读取，新增数据库迁移 `057_order_directory_read_indexes.sql`。

## 升级说明

- 从 v1.1.0 升级需执行数据库迁移 `057_order_directory_read_indexes.sql`。迁移只新增订单目录读取所需索引，不修改订单、资金、库存、会员权益或会话事实。
- 按既有生产流程先保留旧镜像和数据库备份，在隔离副本执行迁移与 readiness 检查，再切换 `compose.server.yaml` 的应用容器。迁移成功后优先以前向修复处理故障；不要直接用旧应用覆盖新数据库。
- 无新增运行时配置。更新完成后刷新浏览器即可；原有登录、Token 权限和业务写入确认协议保持不变。

## 验证与已知问题

- 已通过 `npm run typecheck`、`npm run build` 和 `git diff --check`。
- 已通过本轮新增的读取恢复、订单目录分页、会员目录和用户旅程相关单元、集成及浏览器检查；本地人工验收环境验证了账号图标、房态筛选操作组及高级筛选展开布局。
- 账号管理与会员删除仍保留历史基线契约失败记录，本版本未改变其业务规则，不宣称全量契约测试无基线失败。
- 用户界面人工验收状态按项目验收计划保留为“待反馈”；代码发布和人工验收是两个独立状态。

## 回退说明

- 发布前保留 v1.1.0 镜像和数据库备份。若迁移尚未提交或事务已回滚，可恢复旧应用。
- 迁移成功后旧应用与新数据库的索引结构通常兼容，但回退前仍须停止写入、核对数据库 readiness 和应用版本；不要删除迁移记录或覆盖升级后的业务数据。
- 回退或修复完成后必须重新检查 `/health/ready`、`/api/v1/version`、前端版本和订单/房态读取恢复路径。
