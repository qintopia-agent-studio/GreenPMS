# QinTopia PMS v1.3.1

发布日期：2026-09-10。企业微信收退款能力与相关 PMS 事件接口发布。

## 改动说明

- 新增企业微信对外收款流水的后台同步、付款人昵称缓存、金额/时间/单号查询和最多 5 笔推荐。
- 新增收款与退款的完整清单、状态显示、历史边界、分页和本地数据库读取；页面不直接实时请求企业微信。
- 退款保存独立退款单号，并与同一订单的原收款严格关联；确认提交时防止金额、订单、物业和并发重复错误。
- 弹窗改为主动关闭，点击窗口外部、拖动结束于外部或按 Esc 不再丢失表单；通过“×”或“取消”关闭。
- 增加 `pms.payments.v1` 财务事件读取基础，供后续智能体消费。

- 执行数据库迁移 `058_integration_events.sql`、`059_wecom_refund_reference.sql` 和 `060_external_payments.sql`。
- 默认不启用企业微信 Worker。生产环境需单独配置 `PMS_WECOM_SOURCE_ID`、企业 ID、商户号映射、历史导入起点和独立 Worker 数据库账号后，再设置 `PMS_WECOM_SYNC_ENABLED=true`。
- `matching_since` 按已确认规则使用北京时间 `2026-09-01 00:00:00`；此前未登记流水只作历史资料，不进入推荐或自动提醒。
- 企业微信应用 Secret 只通过服务器环境变量注入，不写入仓库、前端或数据库。
- 处理状态下拉只显示“待匹配 / 全部 / 已匹配”；历史记录在“全部”中查看。

## 验证结果

- 已通过 TypeScript 检查、生产构建、`git diff --check`。
- 企业微信专用客户端与真实快照只读联调通过：9 月 1 日至今 25 笔收款，8 月起 105 笔收款、9 条退款，82 个付款人昵称取得。
- 企业微信本地真实流水体验通过桌面与 375px 手机检查：单层滚动、完整清单、金额自动带入、取消不匹配、历史退款独立编号和显式关闭。
- 相关专项单元/集成测试和既有资金回归已通过；发布脚本测试中有 2 项因本机 Python 不满足安装器的 3.10+ / `venv` 前置条件而未执行到业务断言。
- 本次数据库迁移涉及资金匹配约束，部署前保留数据库备份；未将本地真实流水快照或测试数据库提交到仓库。

## 风险与回退

- 应用代码可回退到 `v1.2.3`，保留已执行迁移，不回退数据库结构或已产生的财务事实。
- 若生产迁移验证失败，停止切换并恢复旧应用镜像；按备份恢复流程处理，不直接删除新表或退款字段。
