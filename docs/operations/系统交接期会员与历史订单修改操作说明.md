# Green PMS 系统交接期会员与历史订单修改操作说明

> 适用版本：Green PMS 第 9.3-9.5 步。请只在生产页面已经显示本文所述入口、并收到正式上线通知后，按本说明操作生产数据。

## 1. 这份说明适用于什么情况

本说明供 Green PMS 管理员处理系统切换、补录或日常操作中发现的以下问题：

- 已完成住宿的日期或房间录错；
- 会员姓名、昵称、证件号、手机号或微信号录错；
- 会员开始日期录错，或工作人员晚录会员；
- 会员实际已经办理，但系统中没有会员订单、合同和权益；
- 错误办理了一张尚未使用的会员卡，需要保留会员档案并按真实住宿和收款重新办理；
- 尚未生效或已经生效的会员订单仍未收足，需要登记实际收款。

管理员拥有普通员工的全部日常操作能力，并增加上述受控修改能力。管理员仍不能直接删除历史记录、随意修改合同或权益、执行 SQL，或绕过系统核对结果。

## 2. 操作前必须准备的资料

开始操作前，请先核实并准备：

1. 会员本人身份和联系方式；
2. 企业微信收款截图或其他可核对的收款凭证；
3. 企业微信交易单号；
4. 真实住宿日期和实际安排的房间；
5. 会员实际开始日期；
6. 能说明为什么需要修改的纸质记录、聊天记录或交接说明。

不要为了让页面通过而改变真实日期、金额、交易单号或会员身份。系统拒绝操作时，说明当前记录不满足这项安全条件，应停止并进一步核对。

## 3. 先判断应使用哪个入口

| 发现的问题 | 操作账号 | 使用入口 |
|---|---|---|
| 已完成住宿的日期或房间录错 | 管理员 | `订单` → `修改历史安排` |
| 会员姓名或联系方式录错 | 管理员 | `会员` → 选择会员 → `修改会员记录` → `修改会员资料` |
| 会员开始日期录错或录晚 | 管理员 | `会员` → 选择会员 → `修改会员记录` → `修改会员生效日` |
| 历史上已经办卡，但系统完全没有有效会员记录 | 管理员 | `会员` → 选择会员 → `修改会员记录` → `补录历史办卡` |
| 错误会员卡尚未使用，需要按历史住宿重新办理 | 管理员 | `会员` → 选择会员 → `修改会员记录` → `撤销错误办卡并重新升级` |
| 尚未生效或已经生效的会员订单仍未收足 | 普通员工或管理员 | 会员订单中的 `收款` |
| 真实退款、真实退会、会员合并或页面明确拒绝的切换期异常 | 暂不在页面处理 | 停止操作并登记给系统负责人 |

## 4. 修改已完成住宿的日期或房间

适用于已经退房或已经完成的住宿。正在入住的订单不能使用这个入口。

1. 使用管理员账号进入 `订单`。
2. 点击 `修改历史安排`。
3. 将需要一起调整的订单全部加入修改清单。
4. 按真实记录填写入住日期、退房日期和房间。
5. 填写事实依据和修改原因。
6. 点击 `生成整组核对`。
7. 核对修改前后内容，确认住客、成交价、收款和订单完成状态均未变化。
8. 确认无误后执行。

如果两位住客的房间互相录反，必须把两张订单加入同一修改清单后一次提交，不能分两次修改。

## 5. 修改会员资料

1. 使用管理员账号进入 `会员`，搜索并打开本人档案。
2. 点击 `修改会员记录`。
3. 选择 `修改会员资料`。
4. 只修改已经核实有误的姓名、昵称、证件号、手机号或微信号。
5. 填写事实依据和修改原因。
6. 生成只读核对，逐项比较修改前后内容。
7. 确认无误后执行。

如果手机号已经属于另一位会员，系统会拒绝。本入口不能合并两名会员，也不能把一人的历史记录转给另一人。此时应先核对会员身份，不要改用他人手机号强行保存。

## 6. 修改会员生效日

会员开始日期决定合同和权益从哪一天开始计算。企业微信收款日期只记录实际收款发生在哪一天，两者没有绑定关系，也没有固定先后顺序。

1. 使用管理员账号进入 `会员`，打开对应会员。
2. 点击 `修改会员记录`，选择 `修改会员生效日`。
3. 填写核实后的会员开始日期。
4. 填写事实依据和修改原因。
5. 生成只读核对。
6. 核对系统重新计算的合同日期和权益日期；产品、收款、权益总量、已用数量和余额应保持不变。
7. 确认无误后执行。

合同结束日期、权益有效期和剩余权益由系统统一计算，不能分别手改。如果新日期会让会员立即过期、恢复已经失效的权益，或使历史住宿落到有效期之外，系统会拒绝，应停止并登记给系统负责人。

## 7. 补录历史办卡

只适用于会员真实办过卡，但系统中没有未作废会员订单、有效合同或有效权益的情况。

1. 先确认会员档案是本人，且系统中确实没有有效会员记录。
2. 点击 `修改会员记录`，选择 `补录历史办卡`。
3. 选择真实办理的会员产品。
4. 填写真实的会员开始日期。
5. 填写企业微信实际收款金额、收款日期和交易单号。
6. 填写事实依据和修改原因。
7. 生成只读核对。
8. 核对会员产品、收款、合同期限和权益数量后执行。

系统会一次建立会员订单、收款、合同和权益。会员权益只按会员开始日期计算；收款日期不需要与会员开始日期相同，也不记录具体几点几分。

历史补录使用所选会员产品的正式价格，不允许在这个入口手工调价。历史折扣、特批价格、已经过期的历史会员，或已经存在有效会员记录的情况，应停止并登记给系统负责人。

## 8. 撤销错误办卡并重新升级

这里的“撤销”是保留全部历史记录并作废错误会员链，不是删除会员，也不是把钱真实退还给会员。

适用条件：错误会员卡的权益完全没有使用；能够唯一确认对应的历史住宿、会员本人和真实收款；此次处理不涉及真实退款。

1. 使用管理员账号打开对应会员。
2. 点击 `修改会员记录`，选择 `撤销错误办卡并重新升级`。
3. 选择系统列出的错误会员订单和对应历史住宿。
4. 填写真实会员开始日期。
5. 如有真实差额收款，勾选差额收款并填写收款日期和交易单号。
6. 填写事实依据和修改原因。
7. 生成只读核对。
8. 核对以下内容：旧收款冲销、历史住宿转入、实际差额收款、新合同期限、历史权益核销和剩余权益。
9. 确认所有金额和日期都与凭证一致后执行。

系统会在一次操作中作废错误订单、合同和未使用权益，保留会员档案和旧历史，再创建正确的新会员订单、合同和权益。冲销金额、住宿转入金额、差额、合同和权益均由系统计算，不得通过修改其他字段把金额凑平。

如果旧权益已经使用、发生过真实退款、历史住宿不是本人、资金无法唯一对应或页面没有提供可选记录，应停止操作。

## 9. 为未收足的会员订单登记收款

普通员工和管理员都可以操作。

1. 打开会员详情，找到显示收款不足的会员订单。订单可以是尚未生效，也可以是已经生效。
2. 点击 `收款`。
3. 系统默认带出当前尚差金额；如果本次只收到一部分，按企业微信真实到账金额填写。
4. 填写企业微信交易单号并生成核对。
5. 核对成交价、此前实收、本次收款和操作后差额，再确认执行。

这项操作只增加一笔真实收款，不改变会员开始日期、合同期限、权益数量或会员状态。已经收足时不再显示 `收款` 按钮。

如果订单尚未生效，登记收款不会自动让会员生效。工作人员仍应根据真实办理情况，另行使用正常的 `生效会员订单` 操作。已经生效的订单补收后仍保持原会员状态，系统不会再次发放权益。

## 10. 操作完成后的检查

每次执行后都应重新打开订单或会员详情，检查：

- 页面显示的当前资料、日期、房间和金额是否正确；
- 修改记录是否包含操作人、操作时间、原因和修改前后内容；
- 会员合同、已用权益和剩余权益是否为系统计算结果；
- 旧订单、旧合同和旧权益是否仍可追溯；
- 住宿、会员和收款之间是否可以相互核对。

发现结果与只读核对不一致时，不要继续做第二次修改，应立即保留页面信息并联系系统负责人。

## 11. 页面不能处理的情况

以下情况不应尝试绕过系统：

- 正在入住的历史合并订单需要拆分或交换；
- 真实退会、真实退款或需要把钱退还给会员；
- 两个会员档案需要合并；
- 已使用权益与新的会员日期不兼容；
- 历史会员已经过期，需要同时恢复或重新扣减权益；
- 历史成交价是折扣价或特批价；
- 收款、会员身份或历史住宿证据缺失，无法唯一确认；
- 在 `补录历史办卡` 或 `撤销错误办卡并重新升级` 中，系统提示企业微信交易单号已经被使用；
- 页面明确提示当前记录不适用。

这些少量切换期问题由系统负责人使用专门程序处理。处理前会逐项核对；执行时要么全部成功，要么全部不生效，并保留完整操作记录。管理员不会因此获得任意修改数据库的能力。

## 12. 当前尚未开放的能力

- 生产中的 108 鹏哥/小尚真实记录属于仍在住的合并住宿，不能直接使用 `修改历史安排`。
- 生产中的 Cathy、晶晶真实记录仍需补齐身份和来源住宿等权威事实，不能因为验收环境中有同名样例就直接照做。
- 会员原房型满房时免费临时安排其他整房的功能尚未上线；当前不要通过错误选择权益或手工改数据绕过房型限制。
- 工作人员账号和密码管理将在后续 9.6 单独开发。

上述记录或能力由后续专门版本处理。管理员页面中的同名验收数据只用于验证功能，不代表生产记录已经具备执行条件。
