# 经营销售额迁移与切换执行准备

状态：准备方案，未执行生产变更。适用迁移071/072/073及经营统计首次初始化；不是新增自动发布流程。业务规则和人工验收见 `../implementation/sales-reconciliation-delivery.md` 及主人工验收计划。

## 必要条件

- 功能PR检查通过，资金流程人工验收完成；正式版本PR记录迁移集合，`rollbackCompatibility` 使用 `forward-only` 并说明追加资金事实及旧镜像读写不兼容。
- 生产只读确认版本、迁移基线、订单当前版本和备份恢复证据。沿用既有发布入口；不在生产构建，不读取凭据文件，不把owner权限放入Actions。
- 固定期初计划及SHA，明确每项来源及已计金额；历史归属关系未解决时保持拒绝初始化；本次387.50元已据用户截图定位后续账单并补入计划，须使用更新后的计划SHA。不得通过清空缺项或按相等金额猜测通过门槛。

## 维护窗口次序

1. 完成必要执行授权后，停止业务写入并确认旧实例与在途命令已静止，按正式数据库维护入口执行071/072/073。072从原定价历史承接渠道事实；迁移后至新应用接管前不能允许旧应用继续写定价修订，否则旧应用不具备新的同步登记逻辑。
2. 校验迁移文件、函数、权限和readiness。初始化使用审核后的固定计划、所有者维护入口及SHA；失败整笔回滚，不能部分留下封账和期初来源。初始化前不开放新渠道退款。
3. 按现有发布runbook核对迁移基线并切换正式预构建镜像，不手改部署状态或跳过门禁。当前发布harness不自动执行迁移，须保持该边界。
4. 使用正式授权身份走Preview/Confirm更正两笔已退房渠道金额，重新校验订单版本；目标分别为1610.28、277.20元，保留旧修订和回执。如已经被更正则核对结果，不重复写入。
5. 读取9月封账净额48649.98元、10月逐笔收入明细、期初来源及新命令回执；确认社区人数、今日指标、退款方向和渠道金额，恢复业务操作。

迁移072的封账限制针对新增退款及其撤销，历史金额更正保留原业务日期；整月销售展示使用固定基准，不因这两笔更正再次增加封账数。独立数据库应覆盖“先初始化、再更正、9月总数不变”的正式命令用例，不能通过改动封账数或绕过守卫解决冲突。

## 故障与回退

迁移和新资金事实写入后，旧镜像不保证能读取、追加这些事实；不能承诺简单镜像回退。现有发布脚本在健康检查失败时会尝试恢复旧容器，该动作不等于数据库已恢复可用。出现该情况保持停写，保留日志、回执和迁移证据，按既有runbook执行经核对的前向修复或数据库恢复；不删除退款/成交历史，不修改CI或发布工作流来绕过检查。
