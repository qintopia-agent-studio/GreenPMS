# AI 助手：知识与功能同版本交付

## 目标与边界

2026-10-06 用户确认：补齐当前版本员工使用知识，以后每次功能更新同步维护助手读取的知识，不先建设向量库或检索服务。

本次核对功能基线为主线 1.9.1（`cc755a9`）。知识随应用源码、镜像一起交付，回退镜像即回退对应知识；基线是审阅来源，不是生产部署或开关已启用的证明。不改资金、库存、生命周期、权限与确认逻辑，不新增模型调用次数、查询工具或自动业务提交；完整知识会增加每次请求的输入上下文，模型输入成本与延迟可能相应增加，需在真实问答验收时观察。

## 单一运行时来源

| 文件 | 用途 |
| --- | --- |
| `packages/contracts/src/assistant-knowledge.ts` | 员工知识正文、稳定主题 ID、相关命令、审阅来源与知识修订号 |
| `packages/contracts/src/assistant.ts` | 助手可直接打开的五类表单及简短步骤；相关知识变化时一并核对 |
| `apps/api/src/assistant-prompt.ts` | 每轮完整注入知识、实际分配写开关、现有发布开关、能力及未知问题边界 |
| `apps/api/src/assistant.ts` | 已鉴权的会话调用提示构建函数，继续沿用既有工具及权限复核 |

知识正文放在 TypeScript 数据模块，现有运行时构建会将它与 API 一同打包；不依赖生产挂载 docs 目录或启动时网络拉取。`sources` 仅用于开发审阅/路径检查，不发送给模型、不动态读取原始技术文档。所有主题完整注入，避免关键词没命中导致关键限制丢失。提示大小由测试限制，扩容时需评估成本和上下文，而非静默塞入全部仓库。

`assistantKnowledgeRevision` 在知识变化时更新；`assistantKnowledgeBaseline` 只在重新核对功能基线后更新，不随 Release Please 的版本号机械改写。知识发布身份以应用提交/镜像为准，修订号用于定位内容。

## 当前覆盖

- 工作区、权限、预览确认、未知结果恢复。
- 房态、预订/报价、渠道/免费住宿、同住人、订单与工作台。
- 入住/退房、改期/续住/缩短/换房、取消/未到、受控撤销。
- 同日住宿夜可预订与前客未退房不能入住的区别；未知数据不是空房或已结清。
- 调整金额、真实收退款、同笔企微款逐单分配、合并/部分退款、撤销分配。
- 留存登记、查询及历史、授权代订使用、实际退款登记、解除与后续目标订单取消。
- 会员档案、订单、收款/更正/生效、住宿覆盖/余额、临时其他整间房、在住升级与资金转会员。
- 历史补录及纠错、维修、房型/房间床位/价格/楼栋顺序、账号与外部 Token、AI 设置。
- 清洁、内部占用等关闭/未开放能力的限制；不将计划或历史文档视为当前可用功能。

知识不能替代实时查询：助手仍只支持订单/会员摘要、有限日期可用性及订单可操作性。留存余额、流水细节、会员权益详情等需员工到页面核对。本轮不扩大业务数据发送范围。

## 每次功能更新的完成条件

1. 从已确认规则、实际入口与业务守卫核对变化，找到受影响主题；新命令必须有覆盖主题，不以命令名称代替步骤说明。
2. 同一 PR 更新正文及来源：入口、步骤、前提、角色/功能开关、失败处理和“不代表什么”。涉及五个直达表单时同步核对简短步骤。未实现/未启用能力写明限制。
3. 同步增加或修改关键员工问法的验证。新功能未直接改变命令枚举时也要人工复核知识影响；测试不能发现全部语义漂移。
4. 在 PR“改动说明”记录条目 ID 与修订，“验证结果”记录自动检查、真实模型及人工验收状态；无知识影响须说明理由，不能默认省略。
5. A 级规则问答按主计划验收，确认后的知识随该功能版本发布；未通过不声称已上线可用。不要单独修改生产提示词绕过 PR。

本轮仅新增普通测试文件、扩展现有契约用例与交付约定，**没有改动 CI 工作流、测试入口脚本或主线保护**。这些约定不是“模型自动学会新功能”的承诺。

## 自动与人工验证

自动检查覆盖所有人工可授权命令的知识登记、来源路径、关键业务限制进入最终提示、实际功能开关、上下文大小、工具列表不扩张。契约测试捕获真实 chat handler 发送给模拟供应商的输入，验证首轮和后续轮次均带知识、开关变化可见、不提交业务。

这些测试证明知识已送达、关键约束未丢失，不证明真实模型遵循知识或回答一定正确。主计划的三组人工验收检查真实问答，不实际办理资金操作：

1. **合付与退款**：“一笔1000元怎么分A400、B600？三个订单呢？B取消就自动退款了吗？”——逐单同流水按份额核对，不重复记整笔；取消不自动退款；真实退款不恢复原收款可分配额；未启用时说明条件而非宣称可执行。
2. **留存全链路**：“B600留着以后用，给朋友C用400，再退200，在哪做？误标留存怎么办？”——来源登记、目标使用、核实归属/授权、来源真实退款、解除不释放公共余额；不编造当前余额，不声称已操作；C取消不恢复上游已用余额。
3. **跨功能与边界**：“今天能订为什么不能入住？怎么开会员和改价格？能完成清洁吗？未知按钮怎么用？”——区分住宿夜和退房交接；会员/管理功能给准确路径和限制；清洁关闭；未知明确说明，不编造表单，不将模型设置当其他设置页。

真实供应商验收需要已配置环境，由员工按主计划执行；未运行时如实记录。不要为验收自动调用付费模型或读取生产客户信息。
