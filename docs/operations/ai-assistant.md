# AI 助手连接与维护

本功能为网页登录用户提供获权查询和操作引导。没有模型配置时，PMS 其他功能正常使用。实际续住、资金和库存变更仍通过原有表单、Preview / Confirm 完成。

提问记录保存在同一数据库的 `ai_question_records`；Codex 应使用 `ai_question_export` 视图和 `ai_question_daily` 汇总。表字段、90 天明细保留和只读同步方式见 [AI 提问记录与 Codex 同步指南](./ai-question-records.md)，无需数据查看界面。

## 首次配置

1. 部署人员生成独立的 32 字节 base64 随机值，例如 `openssl rand -base64 32`，作为服务端 `AI_SETTINGS_ENCRYPTION_KEY`。此值为加密主密钥，不是供应商 API Key。生产 Compose 已支持传入该变量。
2. 通过项目正式发布入口部署含本功能的镜像，依次应用 `062_ai_assistant.sql` 和 `063_ai_question_records.sql`（在主线 `061_room_catalog_management.sql` 之后）。不要在生产目录构建。
3. 管理员登录，在“设置 → AI 助手”填写 HTTPS Base URL、API Key 或 Bearer 访问 Token、模型名称。Base URL 为 API 根地址，如供应商的 `/v1`；系统追加 `/chat/completions`。
4. 点击“测试连接”。使用流式 Chat Completions（`stream:true`、`max_tokens:2048`、function tools），并要求模型返回一次完整工具调用。此测试产生一次供应商请求，不含业务资料，不保存配置。供应商须支持 SSE、分片工具参数和 `[DONE]` 结束标记。
5. 勾选启用并保存。服务地址改变时必须提供新地址对应的 Key；同地址更换模型可以留空保留 Key。失败后先重新载入核对版本，不自动重复保存或测试。

配置是一套 installation 配置，首次保存绑定当前管理门店；仅该门店现行 ADMIN 可维护。其他获权门店用户可以使用助手。此归属不实现 SaaS 租户隔离，后续租户配置必须跟 SaaS 架构统一迁移。

## 日常维护

- 模型服务不稳定时可更换地址/模型/密钥、测试后保存。设置版本有并发冲突保护；新设置使旧对话失效，需要新建对话。
- 可取消启用并保存。关闭现有配置不依赖供应商联网成功，也不要求旧密钥能解密。
- 凭证不回显、不能从页面下载；只可替换。日志及审计不保存密钥。数据库 `ai_settings_audit` 记录配置版本、管理门店、操作人、地址、模型及是否更换密钥。
- 只允许 HTTPS 公网目标，不允许内网/本机/云元数据地址、URL 内嵌凭证或重定向。私有模型应通过经批准的公网 HTTPS 网关接入，本版不开放内网地址白名单。
- DNS 最多5秒，每次模型 HTTP 请求最多60秒，收到响应后的连续静默最多25秒，一次问答（含工具）总预算120秒，浏览器等待上限150秒。响应最多1MB，模型正文最多12000字符，每次问答最多4次模型请求/6个工具。失败不自动重试或重新发起非流式付费请求，错误不转发供应商正文。
- 浏览器以同一 POST `/api/v1/assistant/chat` 请求 SSE，显示思考/查询/回答阶段；“停止生成”、换工作区或退出会取消连接。仅收到最终成功事件才显示反馈、保存会话回答和打开入口；中断时清除不完整草稿。旧 JSON 客户端保留同一请求的兼容返回。
- `AI_MODEL_COMPLETED` 记录轮次、模型耗时和首段文字耗时，`AI_TOOL_COMPLETED` 记录工具名/耗时，`AI_QUESTION_FINISHED` 记录总耗时与结果。按请求日志 ID 关联；失败细分 `AI_MODEL_TIMEOUT`、`AI_MODEL_IDLE_TIMEOUT`、`AI_TOTAL_TIMEOUT`、`AI_CANCELLED`、`AI_HTTP_*`、`AI_INVALID_RESPONSE` 和安全连接错误码。日志不含凭证、供应商正文或业务查询结果；无文字的工具轮可以没有首段文字耗时。
- 浏览器对话仅保存在当前页面内存；服务器会话最多15分钟、12条历史消息，绑定用户/登录会话/门店/配置版本。换店、退出或服务重启后重新开始。多个 API 实例需要 sticky session；本版沿用单实例部署，未实现共享会话。
- 查询只发送完成问题所需的最小字段到配置的模型服务；不发送完整证件号、完整手机号、外部交易号、供应商凭证或 PMS 登录凭证。回复支持段落、强调、列表和表格排版；忽略原始 HTML，不生成模型提供的链接、图片或表单。页面跳转仍只通过经过校验的操作入口。

## 恢复与回退

加密主密钥须与数据库备份分别安全保管，并在恢复时一起恢复。不要重新生成主密钥后继续使用旧密文；若原主密钥丢失，由管理员重新填写供应商 Key 并保存。

新迁移为新增表与函数，不改变订单事实。优先关闭助手回退功能；旧镜像可能因迁移基线不同而拒绝部署，须遵循正式发布工具的迁移/回退检查，不删除业务或审计数据绕过检查。

## 流式代理与超时排查

在站点新增更具体的 `location /api/v1/assistant/`，复制既有 `proxy_pass`、HTTP 版本及转发头，设置以下参数；其他路由沿用原配置。`proxy_read_timeout` 是两次上游读取间的空闲上限，不是问答总时长。应用每10秒输出 SSE 心跳，且发送 `X-Accel-Buffering: no`；代理也应显式关闭缓冲和压缩。

```nginx
proxy_connect_timeout 3s;
proxy_send_timeout 30s;
proxy_read_timeout 180s;
proxy_buffering off;
gzip off;
```

修改前先执行 `nginx -t`，备份站点文件；修改后再次检查语法，再平滑 reload 并核对 `/health/ready`。既有其他配置有错时，不通过重启、删除无关文件或绕过语法检查推进。恢复使用本次备份并重复语法及健康检查。此配置与应用正式发布分别记录，不在生产构建应用。

原界面“模型服务连接失败或超时”来自应用25秒模型请求的统一错误提示；Nginx 60秒超时则通常返回504，两者须分别核对日志，不能仅凭 WorkBuddy 成功或延迟推断根因。流式改善首段内容的可见时间，并不能消除模型服务本身的延迟或中断。

2026-09-20：生产现用供应商的无业务资料流式工具探针 HTTP200，首批数据约3.6秒、完整结束约4.0秒，已确认分片工具调用与结束标记。该结果不是实际复杂问答的延迟保证。AI 专用 Nginx 配置尚未应用：变更前语法检查发现既存 `/etc/nginx/conf.d/00-webhook-capture.conf:8` 文件末尾缺少终止符，未写入站点文件，当前公网健康仍为 ready；需先由该配置维护者修复，再应用已批准的参数。

## 验证范围

自动验证使用合成模型响应与独立 PostgreSQL 库，验证授权、工具循环、导航和业务表单。真实供应商凭证未预置，真实连通性、供应商模型质量与业务人工验收仍由管理员配置后进行。

## 既有生产实例补齐密钥保护

当设置页提示服务端密钥保护未配置、勾选启用后保存变灰时，与填写顺序及供应商选择无关。先由管理员在安装了本节对应发布工具的服务器执行：

```bash
sudo /usr/local/sbin/greenpms-deploy configure-ai
```

此入口不发布新应用版本，不修改供应商配置或数据库。它持有发布锁，先验证原配置 hash、当前镜像及本地/公网健康；只在没有现有加密凭据和运行时密钥时生成 32 字节随机密钥，写入 root-owned `/etc/greenpms/app.env`，并为固定 Compose 的 app 补齐映射。已有合法密钥原样保留；异常、空值或歧义定义拒绝自动覆盖，不执行密钥轮换。不要把 app.env、命令中的凭据或备份内容复制到聊天、Git 或日志。

执行期间会重建当前版本的 app 和 worker，短暂影响访问，请等待命令结束后再保存模型设置。它检查 Docker、本地/公网 ready/version，以及实际应用模块的加密解密自检，通过后才登记新配置 hash，保留 current、previous、迁移基线和发布时间。重复执行不会轮换密钥。

配置前后文件保存在 `/var/lib/greenpms-release/ai-config-*/`（目录 0700、文件 0600）；该备份包含加密密钥，须按生产秘密备份管理，不能随镜像清理或下载至工作区。`audit.jsonl` 只记状态及备份目录名。此密钥必须长期保留：之后在设置页更换供应商、模型或 API Key 都不需要换服务器加密密钥。

失败时按事务恢复原配置和原镜像；断电/中断由既有 recovery timer 或管理员 `sudo /usr/local/sbin/greenpms-deploy recover` 恢复。状态已提交则保留新配置，未提交则恢复旧配置；遇到备份损坏或事务之外的改动会保留 journal 并停止，不覆盖未知配置。不得手改 state.json 或删除 adoption 绕过配置校验。若失败窗口中已保存供应商凭据，须保留新密钥备份并由管理员核对恢复，不能再次生成密钥。

该操作仅管理员可执行，GitHub 专用部署身份不能调用。旧服务器先从已合并的 main 更新 root-owned 发布库 `server.py` 和 `ai_config.py`（核对原库版本、无未完成事务、持发布锁并保留旧库副本），无需重建应用镜像或替换整份生产配置。用户刷新“设置 → AI 助手”后，应能按任意顺序填写信息和勾选启用，再保存；实际模型连接由用户所填供应商参数决定。
