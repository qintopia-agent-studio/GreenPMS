# 原身份恢复

状态文件包含目标门店、base URL、原输入、稳定幂等键、预览以及正式提交结果；不含 Token。保留其私有权限，不删除未知结果的状态，不手改阶段或幂等键。状态文件不是业务授权或实时业务事实。

| 情况 | 下一步 |
| --- | --- |
| Preview 响应丢失 | 用相同输入、命令及状态文件重放 `prepare`。它只重放原预览键，绝不完成业务 |
| 本地拒绝锁定原因不匹配，仍为 PREPARED | 没有发出 Confirm；沿用原状态，省略 `--reason` 后提交，原样采用预览的 confirmationReason，不重新预览 |
| Confirm 或 quote 响应丢失 | `recover --state 路径`，查询原正式 commandType/propertyId/idempotencyKey；不要再次提交或新建状态 |
| 已有正式回执，但回读失败 | 沿用状态再次恢复/回读；正式业务不再 POST。不报告最终核实成功，直到权威结果可读且吻合 |
| 查询 UNKNOWN | 明确待核实；可依据当前 API 恢复契约显式执行 `resolve --state 路径`。它有独立恢复键，body引用原业务键，不是重新办理 |
| 确定 NOT_EXECUTED | 阅读错误及retryable原因。必要时重新查询、重新预览；新状态对应新尝试，旧记录保留。权限/事实缺失必须先解决 |
| 正式 EXECUTED | 核对 commandType、目标对象、专属结果与业务回读；不得重办 |

恢复接口 `/api/v1/command-results` 与 `/resolve` 接受正式命令或 `CREATE_QUOTE`，不接受 `PREVIEW:*`。不知道正式结果时，读取预览 commandId/receiptId 不会给出目标业务完成证据。

脚本输出的 `COMMITTED` 或成功回执只表示指定正式命令的结果。即使自动回读返回200，仍须按业务索引确认目标和状态/金额/事实；不把所有命令套用同一成功字段。发现回执命令类型不符、带 `result.preview`、回读矛盾或响应无法解析时，保持未核实状态，保存原身份并继续有依据的查询，绝不改数据来凑结果。

需要人工决定时，用业务语言说明对象、差异和选择；原因、effectHash和确认布尔值由客户端据已确认事实填写。敏感信息只留最少必要内容。群聊反馈不展示状态文件内容、认证头、客人证件/手机号或巨量原始响应。
