## 已确认规则

- 普通员工和管理员可在已预订、在住整房订单添加同住人；普通、会员、免费整房一致。床位订单不支持，终态订单不支持。
- 所有人共用订单的完整住宿安排，不设置个人到离日期。补录及撤销登记影响整个订单期间的人数；日期调整、换房、续住、退房沿用整单语义。
- 主要入住人不可移除；误录同住人可撤销登记，要求原因，保留原资料和完整前后名单、操作人、时间，不物理删除。
- 昵称、姓名必填，电话、证件选填；同名不自动合并。稳定人员 ID 不复用，历史回执不重写。
- 当前名单人数不超过订单当前有效时间线中每个房间的核定入住容量；不得把床位售卖解释为整房。移除只纠正误录，不表示某人提前离开。
- 人员登记不改变订单日期、状态、库存占用、价格、资金事实、会员关联和权益。不是主要入住人更换或会员主档修改入口。

## 实施边界

- 新命令 `MANAGE_ORDER_OCCUPANTS`，支持 ADD/REMOVE，沿用 Preview/Confirm/Receipt、版本锁、幂等键、原因、同事务审计与房态 revision。
- 追加同住人及撤销事实；有效名单投影服务于订单、房态、人数与换房容量检查。历史创建回执与资料更正仍保留原证据。
- 数据库受限身份仅获得所需追加权限，保留原表不可变约束。新增授权进入员工/管理员精确权限清单，已有独立 Token 不自动扩大能力。
- Confirm 重验订单和容量；两个并发添加只有符合最新版本的一方成功。错误、撤权、重复撤销、容量变化或注入失败不得产生部分写入。
- 页面在订单详情提供添加入口和同住人撤销入口，房态侧栏可进入同一操作。核对显示共用日期、变更前后人数及原因。

## 最低验证

- 创建后及入住后添加；普通、会员、免费；房态今日/历史人数及昵称同步、总容量不变。
- 满房超容量、床位、跨店、只读、终态、删除主要入住人拒绝；换房涉及低容量房间时拒绝。
- 撤销误录后再次添加可用，稳定 ID 不复用；改资料不恢复撤销记录；创建回执不变。
- 陈旧预览、并发、幂等重试、事务回滚、数据库直接写入旁路及权限边界。
- 类型、相关自动回归、受限 PostgreSQL、桌面和手机真实浏览器验证；提供隔离样例。人工确认添加后人数变化、撤销误录和满容量拒绝。

## 升级与回退说明

- 本次发布版本为 `v1.1.0`，优化、升级和回退说明见 `docs/releases/v1.1.0.md`，实际上线结果随发布验证记录。
- 升级前备份数据库，运行迁移 056 并通过数据库就绪检查后启动配套应用。迁移不补录真实人员，也不自动扩展已有独立 Token 的命令上限。
- 新增登记会影响订单完整期间的人数，历史某天的名册也随补录或撤销纠正；不代表各人真实到离时间。
- 已产生新命令后，旧应用不认识新的订单变更类型，不能仅回退应用镜像；回退需保留升级后数据、核对新增操作，并使用匹配的数据库恢复方案。
