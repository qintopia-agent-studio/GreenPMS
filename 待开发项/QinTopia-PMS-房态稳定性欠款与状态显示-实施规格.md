# QinTopia PMS 房态稳定性、预订欠款与状态显示实施规格

## 1. 目标与成功信号

本切片修复房态五秒新鲜度与前端固定轮询产生的写入口闪动，并在不改变订单、资金、库存或生命周期事实的前提下补齐普通直订预订单的欠款提示，统一历史、今天和未来的房态颜色、整房块、床位块和紧凑父房汇总。

- **CAP-1 房态静默续期**
  - **intent:** 工作人员持续停留、填写表单或打开订单上下文时，页面在房态到期前静默取得新投影，不发生按钮反复启用/禁用、抽屉重载或输入焦点丢失。
  - **success:** 正常网络下持续操作至少跨越三个五秒新鲜度窗口，写入口稳定可用，草稿、滚动、选区、抽屉和焦点保持；网络延迟或失败时仍失败关闭且只显示一条稳定提示。
- **CAP-2 预订欠款注意事实**
  - **intent:** 今日及未来普通直订 `RESERVED / PLANNED` 订单的净登记住宿收款低于当前合同金额时，工作人员在整房、床位及折叠父房对应日期都能看到“欠款”。
  - **success:** 零收款和部分收款统一显示“欠款”；足额收款不显示；渠道、免费和会员权益完整覆盖订单不显示；订单生命周期状态仍为“已预订”。
- **CAP-3 清晰且紧凑的房态显示**
  - **intent:** 历史、今天和未来使用同一套逐日视觉语法；工作人员既能区分整房与分床订单，也能把住宿生命周期、登记人数、物理床数和异常待办分开理解。
  - **success:** `RESERVED` 使用 `#F97316`，`IN_HOUSE` 使用 `#0969DA`，完成住宿使用统一低干扰绿色；分床订单使用独立纯色床位块，整房订单使用单日期格内的连续整房块；父房与整房的 `x/y` 统一表示“登记住宿人数/物理床数”，具体床位不重复显示，大床房可显示 `2/1`；左上角只表达来源/类型，右上角只表达欠款、逾期和未退等注意事项。
- **CAP-4 统一日期入口**
  - **intent:** 工作人员只理解“调整住宿日期”和“调整退房日期”，不增加迟录、自助或自动改期等新入口。
  - **success:** `RESERVED` 的现有 `RESCHEDULE_STAY` 入口显示“调整住宿日期”；`CHECKED_IN` 仍只显示“调整退房日期”且不能改入住日。

完成条件为相关 Unit、Integration、Contract/OpenAPI、浏览器 E2E、TypeScript、生产构建和补丁格式全部通过，并启动本地真实版本供逐项人工验收。真实 `qintopia` 数据库不得用于自动写入测试。

## 2. 冻结业务规则

### 2.1 房态新鲜度与写门禁

1. 服务端五秒 `freshUntil` 合同保持不变；不得通过延长 TTL 掩盖前端刷新问题。
2. 前端按服务端 `freshUntil` 在到期前静默刷新；同一查询同一时刻只允许一个请求。
3. 响应到达时若剩余可写时间不足，不得短暂重新开放写入口；应保持失败关闭并立即去重续期。
4. 正常后台续期不显示加载提示，不改变草稿、抽屉、选区、横纵滚动和输入焦点。
5. revision 未变化的续期不得重载选中订单上下文；revision 或权威事实变化时才按既有安全规则失效旧 Preview 或刷新上下文。
6. 真正到期、超时或查询失败时，写入口保持关闭；同一界面只显示一条稳定原因和一个重试入口，不在每个动作下重复文案。
7. 服务端命令事务内的库存、权限、版本和房态重验继续保留；前端静默续期不能替代服务端校验。

### 2.2 欠款资格

1. 欠款判定为 `netRecordedCollectionMinor < currentContractAmountMinor`；净额为零或正数但不足均统一显示“欠款”。
2. 只适用于生命周期一致的 `RESERVED / PLANNED` 普通直订住宿；当前订单与当前 pricing revision 必须完整可核对。
3. 游牧岛、携程、美团等外部渠道订单排除，因为 PMS 不持有完整单笔收款事实。
4. `FREE` 免费入住排除；存在会员或会员合同覆盖关系的住宿排除。
5. 欠款是独立的只读注意事实，不得把 `RESERVED` 状态改写为历史结算状态 `ARREARS`，不得改变占房、动作或筛选语义。
6. “欠款”只显示在该欠款订单当前有效住宿安排覆盖的日期；父房同一日期多笔欠款去重为一个角标。
7. 金额链、当前 revision 或生命周期损坏时继续投影为未知/部分状态并失败关闭，不得猜测为欠款或已结清。
8. `RECORD_COLLECTION / RECORD_REFUND / REVERSE_FACT` 成功写入资金事实时，必须在同一事务内递增房态 revision，使欠款注意事实立即失效并重投影；幂等重放不得重复递增。该 revision 变化不修改资金金额、订单生命周期、库存 Claim 或计价事实。

### 2.3 父房、床位与整房显示

1. 已预订使用鲜橙 `#F97316`；在住使用鲜蓝 `#0969DA`；已完成住宿使用统一低干扰绿色。蓝色、橙色小块只使用纯色，不在 `10x10px` 内放置无法辨认的图标；完成绿色块保留勾，维修/锁房块保留斜纹或斜杠。所有状态图形仍提供完整可访问名称，不能只依赖颜色。
2. 按床销售父房继续完整显示全部住宿人昵称，当前目录最多四人；按床位顺序以固定两列、最多两行排列。
3. 父房行高不得因长昵称增加。每个昵称独立截断；只有真实溢出的昵称显示省略号，并在鼠标悬浮或键盘聚焦时展示完整昵称；完整显示的昵称不得弹出多余说明。
4. 历史、今天和未来的按床销售父房共用同一组件：按 A、B、C、D 或 A、B 的稳定顺序显示约 `10x10px` 床位块，不再因 `serviceDate < businessDate` 回退为“占用”文字。在住为蓝色填充、已预订为橙色填充、已完成为绿色填充、空闲只有边框且内部无填色。
5. `ARREARS` 历史住宿仍表示已经完成但未收齐：使用与 `SETTLED` 相同的完成绿色，再叠加右上角“欠款”角标；不得再用整格暖色把资金结果伪装成另一种住宿生命周期。
6. 可按床销售房间内的分床订单使用独立床位块；整房订单使用一个只存在于单个日期格底部的紧凑连续“整房块”，不得伪装成多笔床位订单，也不得连接成跨日期住宿横条。整房块不重复显示“整房”“1间”或人物图标，使用状态色与状态图标表达生命周期。
7. `x/y` 只在父房汇总行和整房订单行显示，统一表示“该日期登记住宿人数/房间物理床数”，不得改用核定入住容量：四床房两人整房入住显示 `2/4`，一张大床两人入住允许显示 `2/1`。具体 `BED` 销售单元行已精确表示一张床，不再重复显示 `1/2` 或 `1/4`。整房块已经表示房间整体不可再销售，`2/4` 不得解释为仍有两床可售。
8. `y` 必须来自权威 `physical_bed_count`；不得根据房型名称或 `occupancy_capacity` 猜测。若历史资料确实缺失，只显示 `x/?` 并在详情提示补齐基础资料，不得静默换成入住容量。
9. 欠款、逾期预订和逾期未退均为独立注意事实，只显示在格子右上角，不占用昵称或底部图形区域。逾期在住的原有效住宿日期保持蓝色并显示“未退”，但不得因此把计划退房日之后的今天或未来格画成占用。
10. 分床父房的每个床位块必须表达该床真实状态：维修/锁房、不可售或未知床位不得画成空心“空闲”；比例仍只表达登记住宿人数与物理床数，具体可售性由床位块和详情说明。
11. 两人间按床销售使用两个床位块；所有普通住宿只在各日期格显示昵称、状态图形、适用的 `x/y` 和角标，不显示连续文字状态条。工作人员点击任一住宿日期格后，既有的连续选中高亮表示完整住宿周期。维修、锁房等非住宿 `Block` 横条只在事实实际归属的具体销售单元行保留；父房行只通过带斜纹/斜杠的床位块汇总，不重复渲染子床横条。
12. 点击、展开、查看具体床位、住宿人、订单、资金和异常详情的既有能力全部保留；桌面网格、快捷浮层、右侧上下文、移动端和可访问名称必须使用同一状态与角标词汇。
13. 左上角方形角标只表达住宿来源/类型，与右上角欠款、逾期、未退等注意事项彻底分离。外部渠道显示 `Y` （游牧岛）、`X` （携程）、`M` （美团），共用强调色 `#315F78`；免费住宿显示 `F`，使用 `#7C3AED`；会员权益住宿显示 `H`，使用鲜亮黄色 `#FACC15` 和深色文字 `#3F2A00`。普通直订/企业微信不显示角标。同一父房日期内的相同角标去重，不同角标按床位顺序显示，不得与右上注意角标或昵称重叠。
14. 免费住宿快捷框在已有“已预订/在住”标记后依次显示“免费”与“义工/接待”，并以可访问说明公开免费原因。新订单缺少类型/原因或与渠道、会员关系互相矛盾时必须失败关闭；旧历史免费订单缺少分类时可显示“历史未记录”，不得猜测。

### 2.4 日期入口

1. `RESERVED` 保留现有 `RESCHEDULE_STAY` 命令和两个日期输入，仅把工作人员入口统一为“调整住宿日期”。
2. `CHECKED_IN` 保留现有“调整退房日期”，只允许修改退房日；入住后不得修改入住日期。
3. 客人晚到、工作人员漏办入住或未到继续由工作人员使用现有入口判断；系统不自动修改日期、不自动入住、不自动标记未到。
4. 不新增“预订已逾期”“迟录入住”“补办入住”或“自助入住”按钮和操作概念。迟录只在核对结果和审计记录中保留。

## 3. 明确非目标

- 不修改渠道订单结算金额、佣金或平台实收计算；继续由人工处理。
- 不改变收款、退款、订单金额、计价、库存 Claim、会员权益或订单生命周期的业务语义；仅允许资金命令在原事务内同步递增房态 revision，使只读欠款投影及时失效。
- 不新增数据库迁移；若实现发现必须迁移，先停止并重新核对规格。
- 不延长服务端五秒 freshness，不放宽过期房态写门禁。
- 不改变历史已结单、历史欠款、逾期预订或逾期在住的业务事实；本次只统一其视觉投影和跨入口文案，并补齐既有逾期在住事实的“未退”角标。
- 不删除或弱化已验收的昵称、住宿人数、占用比例、订单详情、父房展开或恢复门禁。
- 已验收的房态展示规则优先于本切片新增内容；发现规格、实现或测试与既有验收结论冲突时，必须停止实现并请求确认，不得通过改写旧测试或新规格覆盖既有结论。

## 4. 合同与投影边界

1. `RoomStatusIntervalDto` 增加严格、只读、独立于 `status` 的欠款注意字段与住宿来源类别字段；来源合同传递业务类别及免费类型/原因，不传递颜色或角标字母。contracts、OpenAPI、API schema 和 Web DTO 校验同步更新并保持 `additionalProperties: false`。
2. 房态 Query 在同一 PostgreSQL repeatable-read 快照中读取活动订单当前 revision 与全部住宿收退款净影响，形成欠款注意事实；不得由 Web 根据金额或文案推断。
3. 相同订单跨日期形成的 interval 保持同一欠款注意字段；父房按 service date 从实际覆盖该日的 child/whole-room interval 聚合。
4. 状态筛选和生命周期继续使用 `RESERVED / IN_HOUSE / SETTLED / ARREARS`；欠款注意字段不创建新生命周期状态。
5. revision 未变化必须意味着房态业务事实未变化；前端可据此跳过选中订单上下文重载，但仍更新 `asOf / freshUntil`。

## 5. 失败测试矩阵

### 5.1 房态刷新

- 到期前刷新成功跨越至少三个 TTL，写门禁不发生 `true -> false -> true` 循环。
- 延迟响应到达时剩余可写时间不足，不短暂开放按钮；只触发一次后续刷新。
- 同一查询已有请求时，定时器、可见性变化和人工刷新不得并发重复请求。
- revision 未变化不增加订单上下文 refresh token，不重置报价或表单草稿。
- revision 变化时旧 Preview、动作和订单上下文继续按既有规则失败关闭。
- 查询失败或实际过期时只显示一条稳定提示，快捷浮层不在每个动作下重复原因。
- 滚动、焦点、输入法输入、抽屉和报价在静默刷新期间保持。

### 5.2 欠款投影

- 普通直订 `0 / 部分 / 足额 / 退款后不足` 四组净额。
- 外部渠道、免费、会员权益覆盖三组排除。
- 当前 revision 缺失、金额链损坏、Order/Stay 状态不一致继续 `PARTIAL / UNKNOWN`。
- 整房、两床父房、四床父房、混合在住/预订、一个或多个欠款子床按日期准确聚合且角标去重。
- 欠款字段不改变 `RESERVED`、blocking、Claim、allowedActions、可售性和过滤结果。
- Contract/OpenAPI 拒绝缺字段、额外字段和非法枚举。

### 5.3 视觉与入口

- 精确断言橙/蓝状态 token；整房、具体床位和父房的普通 `ORDER / FREE_STAY` 住宿均不存在 `.room-status-interval` 文字横条；维修、锁房等非住宿 `Block` 横条继续保留。
- 父房不渲染子床维修横条，对应具体床位行仍显示；父房的维修床位只使用斜纹/斜杠小块汇总。
- 整房和具体床位的单一 `RESERVED / IN_HOUSE` 日期格须有明显且均匀的橙/蓝背景，不增加左侧状态色条，且昵称和状态均保留；整房保留人数/物理床数，具体床位不重复显示房间级比例；混合床位父房保持中性背景并由精确蓝/橙/空心床位块表达。
- A-D 色块顺序、两床/四床数量、空闲无填色、`登记人数/物理床数` 与异常角标同时无重叠；历史、今天和未来使用同一床位块组件。
- 具体床位行不显示房间级比例；蓝/橙床位块和整房块内不存在 SVG 图标，完成绿色块保留勾，维修/锁房块保留可辨识的斜纹或斜杠。
- 携程、游牧岛、美团、免费、会员分别形成 `X/Y/M/F/H` 左上角方形角标；普通直订无角标；父房去重汇总且与右上注意角标不重叠。
- 免费订单快捷框显示“免费”、“义工/接待”和完整原因；普通、渠道、会员订单不伪造免费标记。
- 整房订单每个日期格只显示一个紧凑整房块，不显示多床位块、“整房”“1间”或人物图标；四床房两人显示 `2/4`，大床房两人显示 `2/1`。
- 历史 `SETTLED` 使用完成绿色；历史 `ARREARS` 使用相同完成绿色并单独显示“欠款”；逾期在住原有效日期保持蓝色并显示右上角“未退”，不得扩张当前或未来占用。
- 分床父房同日“维修床 + 住宿床”必须把维修床画成锁定状态，不得显示为空心可售。
- 四个普通昵称全部显示；单个超长昵称只截断自身，不隐藏其他昵称，不增加行高。
- 只有真实 DOM 溢出的昵称可触发 mouse/focus tooltip；完整昵称无 tooltip。
- 父房折叠/展开、整房预订、点击订单、手机详情和历史房态保持。
- `RESERVED` 显示“调整住宿日期”；`CHECKED_IN` 显示“调整退房日期”且入住日不可编辑。

## 6. 人工验收范围

1. 在 Arc 保持房态格快捷框、创建订单抽屉和游牧岛报价分别超过 20 秒，输入中文并等待后台刷新；确认无闪动、按钮不反复变灰、输入焦点不丢失、核对可以进入。
2. 在 Windows Edge 重复同一组操作，作为上线后的最终跨平台验证。
3. 查看一笔零收款和一笔部分收款普通未来预订；确认对应日期的床位与折叠父房显示一个“欠款”，足额、渠道、免费和会员订单不显示。
