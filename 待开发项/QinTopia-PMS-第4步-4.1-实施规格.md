## Intent

**Problem:** 服务端已有入住、退房、会员权益核销和清洁任务事实，但工作人员旅程仍暴露 Preview、Confirm、Receipt、内部状态与内部 ID，且缺少覆盖普通、会员、免费住宿和清洁完成闭环的 4.1 专属浏览器验收。

**Approach:** 复用现有事务状态机和房态投影，为入住、退房、完成清洁提供中文业务核对与结果表达；补齐独立 4.1 演示数据和跨 Web/API/PostgreSQL 自动化测试。

## Boundaries & Constraints

**Always:** 状态只允许“已预订 → 在住 → 已退房”；会员只在入住时把仍为 HELD 的覆盖转为 CONSUMED；退房原子生成独立、非阻断的待清洁任务；完成清洁只更新任务，不改住宿历史、库存 Claim 或可售规则；所有非法状态、陈旧确认、并发和重复请求保持零部分写入。

**Ask First:** 若实现必须决定“待清洁是否阻断可售”、改变现有价格/权益规则、或引入新的清洁任务状态，停止并请求用户确认。

**Never:** 不进入续住、缩短、换房、取消、未到或资金功能；不读取旧 PMS/FewohBee；不覆盖既有审计事实；不在工作人员页面显示 `RESERVED`、`CHECKED_IN`、`IN_HOUSE`、`CHECKED_OUT`、Preview、Confirm、Receipt、Command 或内部对象 ID。

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| 普通/免费入住 | 已预订订单 | 房态与详情显示“在住”，无会员权益变化 | 重复或非法入住不写入 |
| 会员入住 | 已预订且存在 HELD 覆盖 | 订单显示“在住”，仅 HELD 覆盖一次性核销 | 重放不重复核销 |
| 退房 | 在住订单 | 显示“已退房”，生成一个“待清洁”任务 | 重复退房不生成第二任务 |
| 完成清洁 | 待清洁任务 | 任务显示“已完成”，住宿历史保持不变 | 重复完成不追加事实 |
| 返回房态 | 履约动作后返回 | 有效 Stay 保持整段选中；失效选择有中文说明与合理焦点 | 不使用旧操作上下文 |

**Acceptance Criteria:**
- Given 普通、会员、免费订单均为已预订，when 分别入住并退房，then 页面依次只显示“已预订、在住、已退房”，会员覆盖只核销一次。
- Given 退房已完成，when 查看并完成清洁任务，then 房态独立显示“待清洁、已完成”，且不改变住宿历史或硬编码阻断可售。
- Given 工作人员操作履约动作，when 核对、提交、恢复或查看结果，then 页面只显示中文业务语义且不泄露技术协议词和内部 ID。
- Given 在住订单已超过计划退房日，when 工作人员办理退房，then 提交前明确显示迟录、原计划退房日、当前办理营业日和金额不变；提交后只追加一次退房事实、结束住宿并释放库存，不重价、不退款、不生成清洁任务。
- Given 在住订单尚未到计划退房日，when 尝试普通退房或先缩短到营业日，then 页面说明当前版本暂不办理提前退房，服务端所有业务事实、命令事实和房态 revision 均零写入。
- Given 订单状态仍为在住但原计划退房日早于营业日，when 工作人员打开房态，then 订单只出现在可进入的待迟录退房异常任务中，当前及未来房格不显示该住客或“在住”且保持可售；完成迟录退房后该任务消失。
- Given 未来入住、逾期入住或提前退房动作被日期门禁隐藏，when 工作人员查看订单操作区，then 同一区域显示“暂不能办理入住/退房”和具体中文原因，不需要向页面下方寻找。
