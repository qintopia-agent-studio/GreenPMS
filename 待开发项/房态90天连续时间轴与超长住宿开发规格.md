# 房态 90 天连续时间轴与超长住宿开发规格

## 1. Why

当前房态页使用约 14 天的切窗方式。工作人员选择跨越多个切窗的住宿日期时，鼠标拖选无法连续跨页，必须反复切换日期范围，容易丢失选区和上下文。少量超过 90 夜的住宿又不适合迫使整个房态网格默认加载 180 或 365 天。

目标是在日常高频操作中提供连续、可滚动的 90 天时间轴，同时允许工作人员通过侧边日期输入处理最长 366 夜的住宿。90 天只是房态查询和交互数据窗口，不是订单期限。

## 2. 已确认且不得重复讨论的产品决策

1. 房态网格加载连续 90 夜的服务端房态数据。
2. 桌面端维持约 14 天的可见/渲染窗口，日期列具有稳定宽度，不压缩成不可读的 90 列。
3. 90 夜位于同一条连续横向时间轴中，用户使用横向滚动条浏览；不能继续以相互割裂的 14 天页面作为主要模型。
4. 鼠标拖选抵达网格左右边缘时自动滚动，并在保持按下状态时连续扩展同一房源的选区。
5. 90 夜以内的住宿可直接在网格完成拖选。
6. 超过 90 夜的住宿使用侧边房源及入住/退房日期输入，不要求在网格中画出完整选区。
7. 当前领域允许住宿最长 366 夜；本增量不把该边界扩大为无限期。
8. Quote、Preview 和 Confirm 必须检查完整住宿区间，而不是只检查当前显示或已加载的 90 夜。
9. 冲突必须返回并展示具体房源和具体日期/区间；冲突在当前时间轴外时，可跳转并重新定位时间轴查看。
10. Confirm 必须在 PostgreSQL 事务中重新校验完整日期区间；陈旧 Preview 拒绝且零业务写入。
11. 不把默认时间轴扩展到 180 或 365 天，也不建设无限滚动时间轴。

## 4. 领域与状态边界

前端必须区分三个不同概念：

| 状态 | 含义 | 上限 |
|---|---|---|
| `timelineDataRange` | 当前 room-status Query 返回的连续数据区间 | 90 夜 |
| `timelineViewport` | 用户当前在横向滚动容器中看到或虚拟渲染的日期列 | 约 14 天，按视口有界变化 |
| `orderDraftRange` | 侧边订单草稿的完整 `[arrivalDate, departureDate)` | 1 至 366 夜 |

不允许把三者复用为同一个 `range` 后再通过 UI min/max 隐式限制。`orderDraftRange` 可以超出 `timelineDataRange`；这时网格只表达二者的交集，完整可售结论仍由服务端检查。

所有日期继续使用半开区间 `[arrivalDate, departureDate)`：入住日计为住宿晚，退房日不占用当晚库存。网格拖到某个日期格表示包含该晚，因此对应的 `departureDate` 是下一自然日。

## 5. Capabilities And Acceptance

### RS-TL-001：默认连续 90 夜数据窗口

**Intent：** 进入桌面房态时，一次获得连续 90 夜的权威投影，为后续滚动和拖选提供同一数据基础。

**Success：**

- 默认查询区间为 `[propertyBusinessDate, propertyBusinessDate + 90 days)`。
- Query 返回的 `dates` 连续、无重复、恰好 90 个服务日。
- 日期跳转后重新建立一个包含目标日期的连续 90 夜数据窗口。
- 切换时间轴起点时尽量保留物业、筛选、展开房间和垂直房源锚点。
- `asOf`、revision、freshness、stale 和 unknown 语义保持现有规则。

### RS-TL-002：90 夜逻辑轨道与约 14 天可见窗口

**Intent：** 用户像使用一条连续时间轴一样浏览 90 夜，而不是翻阅互相割裂的 14 天页面。

**Success：**

- 横向滚动条的总长度代表完整 90 夜。
- 桌面默认可见/虚拟渲染约 14 天，并允许少量 overscan；不能一次把 90 列压缩到视口。
- 日期列、房态格和连续条带在滚动前后保持稳定宽度和准确对齐。
- 旧的前后日期按钮若保留，只作为按一段日期跳转的快捷方式；它们不得重建成分页模型，也不得无条件清空仍有效的选区。
- sticky 房源轴和日期轴在任何滚动位置保持不透明、可读且不遮挡焦点。
- 页面主体不产生横向溢出，只有标注清楚的房态容器横向滚动。

### RS-TL-003：拖选边缘自动滚动

**Intent：** 用户可以从初始可见日期开始，保持鼠标按下并跨越多个可见窗口选择同一房源的连续区间。

**Success：**

- pointer 按下后进入选区状态；靠近容器左/右边缘时开始水平自动滚动。
- 自动滚动持续更新当前日期命中位置和 `[arrivalDate, departureDate)`，不会改变选中的房源行。
- 向右和向左反向拖选都正确。
- `pointerup`、`pointercancel`、Escape、组件卸载或失去有效选区时立即停止滚动循环。
- 到达 90 夜数据边界后停止，不自动扩展成第 91 夜；界面提示可使用侧边日期输入处理更长住宿。
- 拖过已有冲突时不静默截短或自动换房；保留用户选择并以 blocking conflict 禁用后续写动作。
- 拖选本身只修改客户端草稿，不创建 Quote、Claim、Order、Block、Command 或 Receipt。
- 键盘 `Shift + ArrowLeft/Right` 在虚拟窗口边界继续扩展选区，并自动把焦点日期滚入可见区域。

### RS-TL-004：超过 90 夜的侧边日期输入

**Intent：** 少量长住订单无需把房态网格扩展到 180/365 天，也能通过完整日期输入进入同一权威业务流程。

**Success：**

- 侧边面板允许选择稳定的房间/床位销售单元、入住日期和退房日期。
- 日期不再受当前 `board.range` 的 min/max 限制。
- 有效范围为 1 至 366 夜；空值、无效日期、退房不晚于入住以及 367 夜以上在客户端和服务端均明确拒绝。
- 117 夜示例显示：`2026-07-26 至 2026-11-20，共 117 夜；房态视图当前仅展示其中 90 夜。`
- 90 夜以上的草稿仍能进入与 Web/API 相同的 Quote、Preview、Confirm、幂等和 Receipt 流程。
- 网格不伪造未加载日期的可售状态，也不尝试把 117 夜压缩到 90 格中。
- 移动任务流也提供等价的房源及日期输入，不要求渲染桌面二维矩阵。

### RS-TL-005：完整住宿区间的服务端校验

**Intent：** 90 夜数据窗口永远不能成为库存校验边界。

**Success：**

- Quote 对完整 `orderDraftRange` 逐日检查整房/床位双向互斥。
- CreateOrder Preview 基于完整区间生成 effect 和库存 basis。
- Confirm 在 PostgreSQL 事务内锁定并重新校验完整区间后才写入。
- 冲突发生在第 91 夜以后时，Quote/Preview 仍拒绝并返回实际冲突。
- Preview 后若第 91 夜以后的库存被并发占用，Confirm 返回 `PREVIEW_STALE` 或等价稳定错误，订单、Claim、会员权益和其他业务事实均为零新增。
- 重复 Confirm 与幂等重放继续返回原 Receipt，不重复产生事实。

### RS-TL-006：精确冲突展示与时间轴跳转

**Intent：** 操作员能够知道长住宿为什么失败，并直接定位到相应日期和房源。

**Success：**

- Quote/Preview 的 blocking conflict 返回结构化列表，不只返回通用 `INVENTORY_CONFLICT` 文案。
- 每个冲突至少包含：请求库存单元稳定 ID、实际阻断库存单元稳定 ID、roomId、重叠 `[startDate, endDate)`、blocking fact/source kind，以及获权后的稳定来源引用。
- 无权读取的来源按现有授权规则 redaction，不泄露对象存在性或个人信息。
- Web 显示房间/床位名称、具体冲突日期或区间和阻断类型。
- 每项冲突提供“在房态中查看”动作。目标日期不在当前 90 夜范围时，重新查询一个包含该日期的 90 夜窗口，并把相应房源与日期滚入可见区域。
- 跳转不得丢失原长住宿草稿；返回报价区域后仍保留输入。

推荐复用已有 `RoomStatusConflictDto` 的字段语义，并通过 additive DTO/OpenAPI 扩展将其带入 Quote/Preview 错误详情。不得在 Web 中通过 `blockingClaimIds` 自行拼凑权威冲突。

### RS-TL-007：恢复、新鲜度与并发安全

**Intent：** 页面刷新、详情往返和冲突跳转后仍保留操作上下文，但绝不复用陈旧可售结论。

**Success：**

- 恢复快照包含时间轴数据起点、横向逻辑位置、垂直房源锚点、筛选、展开状态、焦点、网格选区和侧边长住草稿。
- revision 未变化时恢复原位置；revision 变化时先刷新并重新校验。
- 当前焦点日期仍在 90 夜范围内时滚回该日期；不在时给出明确恢复说明。
- stale、unknown、部分投影或刷新失败时保留草稿但阻断依赖可售结论的业务写入。
- 冲突跳转、Quote 失败或 Preview stale 均不能清空工作人员已经输入的长住日期。

### RS-TL-008：响应式与无障碍

**Intent：** 连续滚动和自动滚动不能破坏现有 WCAG 2.2 AA 与移动任务式体验。

**Success：**

- 横向滚动区域具有清晰 accessible name，并说明方向键与 Shift 扩展选区的操作语义。
- 所有网格日期仍具有房源、日期、状态和来源的 accessible name。
- 自动滚动期间焦点可见，不被 sticky 轴或 overflow 裁切。
- 不依赖鼠标：键盘和侧边日期输入可以完成同等日期选择。
- `prefers-reduced-motion` 下不使用平滑动画，但功能保持完整。
- 200% zoom 与 320 CSS px reflow 无文本、焦点、错误摘要或动作重叠。
- `<576px` 继续使用任务式界面，不缩小完整 90 天矩阵。

### RS-TL-009：性能与有界渲染

**Intent：** 加载 90 夜不能通过无界 DOM 或删除业务语义换取表面完成。

**Success：**

- 正常 90 夜 room-status Query P95 `<=500ms`。
- 200 个库存单元 x 90 夜在 `<=2s` 内呈现可键盘交互首屏。
- 日期列使用窗口化/虚拟化或等价有界技术；DOM 数量不能简单按全部房源 x 90 列无限增长。
- 若房源行因多人间完整昵称产生可变高度，虚拟化必须测量并稳定缓存真实行高，不能以固定高度裁掉昵称或造成滚动位置漂移。
- 虚拟化前后连续条带、父子房源、Tooltip、选区、焦点、稳定引用和冲突语义保持准确。
- 自动滚动使用单一有界调度循环；不得累积 timer、animation frame 或全局 pointer listener。

## 6. 目标交互旅程

### 6.1 90 夜内跨窗口拖选

```text
进入房态
  -> 服务端返回连续 90 夜
  -> 首屏看到约 14 天
  -> 在目标房源日期格按下鼠标
  -> 拖到右边缘
  -> 时间轴自动向后滚动
  -> 选区持续扩展
  -> 松开鼠标
  -> 侧栏显示完整半开日期、晚数、房源和冲突
  -> 自动显示住宿金额或进入其他允许动作
```

必须用真实浏览器演示：从 `2026-07-26` 开始，跨越初始可见窗口拖选至至少 `2026-08-20`；选区不能在窗口边界中断。

### 6.2 超过 90 夜住宿

```text
选择房源
  -> 在侧栏输入 2026-07-26 / 2026-11-20
  -> 显示 117 夜及 90 夜视图提示
  -> 自动计算住宿金额
  -> 服务端检查完整 117 夜
  -> 无冲突：点击创建订单并查看订单概述
  -> 有冲突：列出房源与日期，可跳转房态查看
  -> 工作人员确认创建订单
  -> 服务端再次检查完整 117 夜
  -> 成功后显示订单号与下一步操作
```

### 6.3 第 91 夜以后并发冲突

```text
长住订单概述校验成功
  -> 另一个事务占用第 100 夜
  -> 工作人员确认创建订单
  -> 服务端判定原概述依据已变化
  -> 后台保存可恢复的未执行结果
  -> 零订单、零 Claim、零会员权益和零资金事实写入
  -> Web 提示房态已变化，显示冲突日期并保留原草稿
```

## 7. UI 与视觉标准

- 遵循 `design-system/qintopia-pms/MASTER.md`；不得创建第二套 token 或组件语言。
- 房态保持安静、高密度、工作导向，不使用 Hero、营销文案、装饰渐变或卡片套卡片。
- 日期列和房源列尺寸稳定，滚动或 Hover 不造成布局跳动。
- 多人间父房行允许为直接显示最多四个住客昵称而增高；同一房行的全部日期格必须共享该高度并保持对齐，滚动或虚拟化不得重新折叠成“首个昵称 +N”。
- 使用 Lucide 图标；不熟悉的图标必须有 Tooltip。
- 状态始终由文字/图标/纹理表达，不能只依赖颜色。
- 长住提示属于上下文事实，不使用 Toast 作为唯一载体。
- 推荐文案：
  - `已选择 25 夜：2026-07-26 至 2026-08-20。`
  - `该住宿共 117 夜；房态视图当前仅展示其中 90 夜。`
  - `104-A 在 2026-10-31 被订单 QT-1042 阻断。`
  - `房态已经变化，订单尚未创建。请核对完整住宿区间的冲突日期。`

## 8. API、DTO 与 OpenAPI 标准

1. 保持 `/api/v1` 的版本化与授权模型；Web 和外围 API 客户端使用同一领域服务。
2. `room-status` Query 上限保持 90 夜，并在 OpenAPI 中显式记录。
3. 订单/报价日期上限继续由领域的 366 夜约束控制，不复用 room-status 的 90 夜上限。
4. Quote/Preview/Confirm 只接受稳定 inventoryUnitId，不接受自由文本房号作为权威键。
5. 冲突详情使用结构化 DTO，包含稳定引用和半开日期；错误码保持稳定。
6. Preview/Confirm 仍要求 reason、显式确认、effect hash、幂等键和 correlation ID。
7. Confirm 时的冲突结果及 NOT_EXECUTED Receipt 必须可持久查询，网络中断后可恢复。
8. 新字段采用 additive 方式扩展 contracts、TypeBox schema、OpenAPI、Web types 和 contract tests；不得让 Web 私有猜测字段形状。
9. Base 或其他外围投影不能写回库存事实，也不能成为长住校验依赖。

## 9. 不变量与失败关闭

- 90 天是展示/查询窗口，不是住宿期限。
- 侧栏可输入的日期不等于可售；只有服务端完整区间校验可以得出结论。
- unknown、stale、PARTIAL、DTO 缺失或 blocking conflict 绝不能显示为可售。
- 不自动换房、不静默缩短日期、不跳过第 91 夜以后的冲突。
- 拖选、滚动、日期输入和跳转本身均不写业务事实。
- 整房和所有子床位继续双向互斥；不同兄弟床位可同时占用。
- 订单金额、会员 coverageSet 和计价政策不由本增量修改。
- 免费入住、会员入住、人工指定最终总价和资金事实沿用既有领域规则。

## 10. 实施建议与文件所有权

推荐按以下切片推进，每个热点文件只能有一个写入负责人：

2. **连续时间轴切片**：90 夜 Query、横向逻辑轨道、日期虚拟化和滚动恢复。
3. **拖选切片**：边缘检测、自动滚动、跨窗口选择、pointer 生命周期和键盘等价路径。

6. **跳转与恢复切片**：冲突日期定位、重新查询 90 夜窗口、返回报价草稿。

## 11. 自动化验收矩阵

### 11.1 Unit / Web State

- 默认时间轴数据范围恰好 90 夜。
- 日期索引、像素滚动位置和 serviceDate 双向映射正确。
- 约 14 天窗口及 overscan 在开头、中间和末尾正确 clamp。
- 鼠标向右、向左边缘滚动持续扩展同一房源选区。
- pointerup、pointercancel、Escape 和卸载均停止自动滚动。
- 日期窗口移动不再错误清空有效选区、焦点或长住草稿。
- 1、90、91、366、367 夜输入边界正确。
- 恢复快照可重建时间轴起点、scrollLeft、选区和侧栏草稿。

### 11.2 PostgreSQL Integration

- room-status 接受 90 夜并拒绝 91 夜 Query。
- 117 夜 Quote/Preview/Confirm 在完整区间无冲突时生成全部逐日 Claim。
- 第 91 夜以后存在整房 Claim 时，子床长住失败；子床 Claim 也阻断整房长住。
- 不同兄弟床位在完整长住区间内仍可并存。
- Preview 后第 91 夜以后出现并发占用，Confirm stale 且零业务写入。
- 366 夜被领域接受，367 夜以稳定校验错误拒绝。
- 幂等重放不重复创建订单、Claim、Receipt 或其他事实。

### 11.3 API / OpenAPI Contract

- room-status 的 90 夜上限保持在 OpenAPI。
- 长住 Quote/Preview DTO 接受完整 366 夜边界。
- blocking conflict 的结构化字段、稳定 ID、日期和 redaction 被 contract test 锁定。
- Confirm stale 的错误和持久 NOT_EXECUTED Receipt 可通过命令结果查询恢复。
- Web DTO 与 OpenAPI schema 不分叉。

### 11.4 Browser E2E

- `1440x900`：90 夜数据已加载，横向滚动条覆盖完整时间轴，初始可见约 14 天。
- 从 `2026-07-26` 拖到 `2026-08-20`，跨越多个虚拟窗口且选区连续。
- 向左反向拖选和在连续条带上拖选同样有效。
- 自动滚动期间 sticky 轴不遮挡、焦点可见、页面主体无横向溢出。
- 多人间 `2/4、3/4、4/4` 父房格在时间轴起点、中段和末端都直接显示全部有权昵称，不出现 `+N`，横向滚动前后行高和日期对齐不漂移。
- 键盘 `Shift + ArrowRight` 跨越虚拟窗口并保持选区。
- 侧栏输入 `2026-07-26` 至 `2026-11-20`，显示 117 夜提示并发送完整区间。
- 第 100 夜冲突展示具体房源/日期；“在房态中查看”能定位目标。
- 冲突跳转后返回报价，原房源与 117 夜草稿仍存在。
- 订单概述后出现并发冲突，页面说明订单尚未创建、展示冲突日期且不盲目重试。
- `1024x768`、`768x1024`、`375x812`、320 CSS px 和 200% zoom 无重叠或裁切。
- Axe、键盘、focus-visible、reduced-motion 和屏读名称通过。

## 15. Non-Goals

- 不建设 180/365 天默认网格或无限时间轴。
- 不允许在网格拖选第 91 夜；超出部分使用侧边日期输入。

- 不改变计价档位、舍入、政策锁定、会员覆盖或免费入住规则。
- 不做自动换房、智能排房、冲突自动消解或静默缩短住宿。

- 不改造成通用甘特图、日历库或可配置低代码组件。
