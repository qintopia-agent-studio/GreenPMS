# 房态快捷弹出框：订单摘要与常用操作

状态：第一阶段快捷框精简已按 2026-09-20 用户确认提交，PR #44。用户随后明确要求开始互动优化，第二阶段已实现、待反馈；当前交互以文末第二阶段约定为准。以下第一阶段记录保留原有验收事实，不将自动检查代记为人工通过。

## 目标与范围

既有订单的房态快捷框目前需要继续打开订单概览，才能办理入住、退房、日期调整、换房；收款还需进入完整订单再次点按钮。本次在现有点击打开的快捷框中加入摘要和常用动作，直接使用已有办理能力。可售“创建订单”改为“预订”，仍由 CREATE_ORDER 创建预订，入住单独办理。

复用现有房态选择、拖选、键盘、弹出框焦点和关闭方式。详情继续通过页面原有的右侧抽屉入口打开。一个选区包含多笔订单时先明确选择订单，不默认操作第一笔。没有唯一稳定订单引用时不显示可执行动作。

按用户最新反馈，浮层宽度收紧为 300px，小视口保留左右各 8px；桌面按钮高 28px、双列排列，触控保持 44px。此决定替代上一版 360px 及 U2 早期 280px 上限。仍在触发行上方或下方定位，空间不足时内部滚动。

## 既有业务依据

- U1 共享命令外壳、4.2 日期调整、4.3 提前退房、4.4 换房、4.5 生命周期、4.6 收退款规格继续有效。
- 普通会员按 2C 与后续日期/换房规格办理；在住升级会员与跨房型升级按对应最新已确认规格办理。会员身份与本次使用会员权益分别判断。
- 房态/订单身份、当前权限、投影有效性、服务端 allowedActions、自动核对与正式确认、幂等和未知结果恢复均沿用原规则。
- 不改计价、资金、库存、会员权益、数据库或 API 授权语义；不启用清洁，不改 CI 或其调用入口。

## 展示与入口

| 目标 | 首层候选动作 | 摘要 |
| --- | --- | --- |
| 可售 | 预订、维修锁房 | 房源与所选日期 |
| 已预订 | 办理入住、登记收款/查看账务、调整住宿日期、换房 | 住客、日期、住宿金额、已记录净收款、差额 |
| 在住 | 正常/提前退房、资金/权益入口、调整退房日期、换房 | 住宿阶段与资金/权益事实分开 |
| 已退房 | 合法收款、查看账务 | 保留后续资金办理入口 |
| 普通会员全覆盖 | 正常/提前退房、查看权益、调整退房日期、换房 | 本次使用产品、已冻结/核销、匹配权益余额 |
| 会员有现金差额 | 正常/提前退房、登记收款、调整退房日期、换房 | 权益摘要与现金差额；会员档案可达 |
| 已升级会员原住宿 | 合法履约/日期/换房、查看权益 | 关联会员；原住宿不再追加收退款 |
| 临时跨房型 | 合法退房/缩短、查看权益 | 不能续住/换房的既有原因 |
| 免费、外部渠道 | 按已有授权显示履约和日期动作 | 免费原因或渠道应结摘要，不冒充已支付/无欠款 |

最多四个首层动作，每个场景最多一个突出按钮。快捷框删除“查看订单详情”“更多操作”“查看房态记录”。取消、未到、撤销、退款、调价、同住人等继续从原右侧抽屉办理，抽屉仅补齐冲销与会员档案缺少的入口，不重排布局；原核对和授权继续有效。暂不可执行的常见动作显示具体原因；无权限的动作依原授权隐藏。

普通退房仍限计划退房日及之后，提前退房使用 SHORTEN_STAY，入住当天不开放。日期按钮沿用“调整退房日期”，合法续住/缩短由已有表单判断。普通会员已核销权益不因缩短自动退回；在住升级会员恢复未来未使用权益的规则保持不变，不在快捷框自行计算返还。

金额和权益来自通过校验的权威订单与会员响应。净收款已包含退款/冲销影响；差额可能为负，不统一标为应收。“已付清”只影响入口主次，不产生新的住宿状态或收款禁令。退款参考额不等于逐笔可退额度。

## 实现与安全边界

- 快捷框选中单笔订单时复用当前订单读取与响应取消/身份校验，加载失败提供重试；跨订单迟到响应不覆盖当前目标。
- 订单读取沿用房态查询的超时上限；超时停止旧响应并提供重试。刷新、只读及恢复阻断直接反映到快捷按钮上。
- 入住、退房、日期、换房、生命周期操作复用 InventoryPage 现有入口和命令外壳。
- 从完整订单提取共享收退款表单，让详情页与房态页使用同一校验和请求构建；保留资金凭证、逐笔退款限制、草稿返回、单次正式确认与原键恢复。
- 开始办理、提交表单和正式确认继续检查目标、权限和版本。查询或点击按钮本身不写业务事实。
- 查看账务/权益打开既有订单概览或会员档案的对应区域。成功后刷新房态、订单与会员摘要并恢复房态位置。
