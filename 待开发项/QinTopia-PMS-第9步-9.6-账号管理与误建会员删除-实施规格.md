## 追加范围（2026-09-06）

- 用户明确要求：已办理会员但尚未核销权益的会员也需要能够删除，原版本“存在办卡记录即拒绝”的限制需要调整。
- 用户确认收款处理：仅处理误录，保留原收款并追加冲销，作废办卡与未用权益，不发生真实退款。存在待冲销收款时，管理员必须另行勾选确认这些收款为误录。
- 用户确认预订处理：先取消相关预订并释放占用，再允许删除会员；不在删除中自动取消住宿订单。
- 资格覆盖所有关联会员订单、合同、权益批次和住宿：历史核销、住宿转会员、尚未取消的住宿、仍被占用的权益、无法解释的余额调整、外部门店关联均拒绝。只有已释放的预订历史不再阻挡删除。手机号仍可重建。
- 二次确认展示办卡数量、待作废权益和待冲销金额，快照涵盖全部相关业务记录。确认事务锁定会员及关联业务，重新核对快照；冲销、作废、业务删除和审计原子提交。删除后拒绝新增收款或权益引用。
- 自动检查覆盖追加范围，人工验收尚未完成。新迁移 054 追加删除根记录，以独立删除操作关联收款冲销及权益作废；原始命令、收款和权益记录保持不变。

## 已确认边界（2026-09-06）

- 管理员仅管理当前门店的普通员工，不能新增管理员、改角色、重设其他管理员密码或停用其他管理员。所有工作人员可凭当前密码修改自己的密码。
- 普通员工管理包括创建（账号、显示名、初始密码）、重设密码、停用、重新启用、撤销全部会话。仅误建且从未登录、未签发 Token、无操作记录的空员工可删除；其他员工保留历史身份。
- 账号页先展示“在用员工”，下方独立展示“已停用员工”。停用及启用成功后移入对应栏目，保留原有操作权限与历史。
- 员工真正删除仅用于 9.6 页面新建的空账号；初始化账号仍属于部署权限名单，保留停用能力，不删除，以保证后续升级与 readiness。会员删除不受账号来源限制。
- 可删除无业务记录以及已办卡但从未核销权益的误建会员；有关联预订时先取消，误录收款按追加范围同步冲销。单门店范围，不删除其他门店会员或跨门店共享档案。
- 会员采用业务删除，保留原档案、建档/资料纠正/删除审计；日常列表、查询及业务选择不再提供，不能继续办卡或下单；手机号可重新建档，不合并历史身份。
- 删除必须显示目标姓名、昵称、手机号，并由管理员填写原因、二次确认。确认时重新核对目标快照、当前权限与业务关联；并发新增业务与删除只能有一个成功。

## 接口与事务

- 账号管理采用独立的网页登录安全接口，禁止 Bearer Token 调用。密码不进入通用业务命令的预检、回执、草稿或审计。接口严格校验字段和长度，写入使用请求 ID 去重，结果不包含密码或哈希。
- 数据库运行身份仍不能直接修改主体、角色或权限；受控 SECURITY DEFINER 函数固定 search_path、撤销 PUBLIC 执行权，重验当前会话、主体、门店 WRITE 和管理员角色。自身改密校验旧密码，提交时重验原凭据版本。
- 创建员工固定 STAFF，复用 STAFF 权限目录。权限投影摘要同步更新；既有清单协调在升级后继续保留新增 STAFF，不能恢复被撤销的会话或 Token。
- 停用员工原子增加 auth_version、撤销全部 Web 会话和 API Token。重新启用不恢复旧凭证。密码变更增加 auth_version 并撤销全部 Web 会话，独立 API Token 沿用既有规则，不随普通改密自动撤销。
- 重设密码不改变账号启停状态；停用账号须在启用后才能使用新密码登录。重设弹窗及成功提示明确显示停用状态。
- 登录签发会话时在同一事务锁定并重验主体版本，避免旧密码校验与改密/停用并发后产生有效旧会话。
- 会员删除由受控数据库函数写入不可变操作记录和 deleted_at；不授予 runtime 直接删除/恢复权限。所有新增会员业务引用通过行锁校验会员未删除；有效档案手机号唯一约束保持数据库级并发保护。
- 成功写入和脱敏审计同事务；失败不写业务事实。重复请求返回同一结果，目标版本改变拒绝；页面遇到结果不明时保留请求 ID 以便核对/重试。
